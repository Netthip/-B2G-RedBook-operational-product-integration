## 2. ข้อมูลไปอยู่ที่ไหน

ทุกตำแหน่งอยู่ใต้ `REDBOOK_DATA_DIR` ตัวเดียว (`redbook/config.py`)
ค่าเริ่มต้นคือ `<repo>/.data` และ **ตั้งใจให้อยู่นอก OneDrive** เพราะโฟลเดอร์ที่
sync ขึ้นคลาวด์เท่ากับการส่งข้อมูลออกนอกเครื่อง

| ที่เก็บ | เนื้อหา | ล้างเมื่อไร |
|---|---|---|
| `uploads/` | ไฟล์ที่อัปโหลด **ตามต้นฉบับ** | 🔴 **ไม่มีการล้างอัตโนมัติ** |
| `tmp/` | ชิ้นส่วนระหว่างอัปโหลด (`upload_*.part`) | ล้างตอนแอปเริ่มทำงาน ถ้าเก่ากว่า **1 ชั่วโมง** (`filestore.purge_temp`) |
| `redbook.sqlite3` | โครงงาน · ไฟล์ · การรัน · finding · คำตัดสิน · audit log · ตาราง `t1b_*` | 🔴 **ไม่มีการล้างอัตโนมัติ** |
| `logs/app.log` | บรรทัดล็อกของแอป | 🔴 **ไม่มีการหมุนไฟล์และไม่มีการล้าง** |
| `exports/` | โฟลเดอร์ถูกสร้างไว้ **แต่ยังไม่มีอะไรเขียนลงไป** | — |

### สิ่งที่ **ไม่** ถูกเก็บ

* ไม่มีการเก็บรหัสผ่าน — ระบบไม่มีระบบบัญชีผู้ใช้เลย
* ไม่มี cookie ติดตามผู้ใช้ — มีแต่ cookie CSRF ที่หมดอายุตามเซสชัน
* ไม่มีการเก็บ IP นอกจากในตาราง `security_events` เมื่อ CSRF ถูกปฏิเสธ

## 3. ข้อมูลออกนอกเครื่องไหม — **ไม่**

| ช่องทาง | สถานะ | ที่บังคับไว้ |
|---|---|---|
| การผูกพอร์ต | `127.0.0.1` เท่านั้น | `config.BIND_HOST` · เครื่องอื่นในวงแลนเรียกไม่ได้ |
| ไลบรารีเครือข่ายในแพ็กเกจ | **ห้ามทั้งตระกูล** | `tests/test_architecture_separation.py::test_no_outbound_network_libraries` |
| ทรัพยากรภายนอกในหน้าเว็บ | **ห้ามทั้งหมด** | CSP `default-src 'none'` (`redbook/web/security.py`) |
| เอกสาร API (`/docs`, `/openapi.json`) | ปิด | `docs_url=None, redoc_url=None, openapi_url=None` |
| การส่งข้อมูลไปบริการภายนอก | ไม่มีจุดใดในโค้ด | — |

🔴 **ช่องทางที่ยังเปิดอยู่โดยธรรมชาติ** — ไฟล์ CSV ที่ผู้ใช้เปิดด้วย Excel
สามารถเรียกเครือข่ายได้เองผ่านสูตร (`=WEBSERVICE` · `=HYPERLINK`)
กันไว้แล้วที่ `redbook/export/csv_safe.py` **ก่อน**ที่จะมีการส่งออกใด ๆ เกิดขึ้น

## 4. การกลบข้อมูลก่อนออกจากระบบ

`redbook/privacy.py` บังคับสามข้อ (ดู `tests/test_privacy_leakage.py`)

| ปลายทาง | สิ่งที่ถูกกลบ | ที่บังคับ |
|---|---|---|
| ล็อกของแอป | เส้นทางไฟล์สัมบูรณ์ **ทุกบรรทัด** รวม traceback | `RedactingFormatter` ที่ formatter ⇒ ครอบทุกจุดที่เรียก `log.*` |
| หน้าเว็บ | เส้นทางสัมบูรณ์ · ข้อผิดพลาดภายในดิบ | `fail()` + projection ของ `services/t1b.py` |
| แฟ้มที่ตั้งใจจะแชร์ | เส้นทาง **และชื่อไฟล์** | `privacy.redact_obj(..., filenames=True)` |
| CSV ที่จะส่งออก | เส้นทาง + สูตร + อักขระควบคุม | `export/csv_safe.py` · ปฏิเสธการเขียนถ้ายังรั่ว |

## 5. การลบข้อมูล — สถานะจริงวันนี้

| สิ่งที่ต้องลบได้ | มีทางลบไหม | หมายเหตุ |
|---|---|---|
| รอบตรวจ T1B หนึ่งรอบ | 🟢 **มี** — `t1b_repo.delete_run()` | ลบทั้ง `t1b_runs` และ `t1b_findings` ของรอบนั้น |
| ไฟล์ที่อัปโหลด | 🔴 **ยังไม่มี** | ต้องลบด้วยมือจาก `uploads/` |
| โครงงานและการรันของ T1A | 🔴 **ยังไม่มีทางลบผ่านหน้าจอ** | `ON DELETE CASCADE` มีในสคีมาแล้ว แต่ไม่มี route |
| `audit_log` | 🔴 **ลบไม่ได้โดยเจตนา** | trigger `audit_log_no_update` / `audit_log_no_delete` |
| ล็อกของแอป | 🔴 ยังไม่มีการหมุนไฟล์ | ลบด้วยมือได้ |

### 🔴 ข้อขัดแย้งที่ต้องรู้ตั้งแต่ตอนนี้

`audit_log` ถูกออกแบบให้ **ลบไม่ได้** เพื่อให้ audit trail เชื่อถือได้
แต่รายการใน `detail_json` มี **แฮชของไฟล์และชื่อหน่วยงานที่ผู้ใช้กรอก**
⇒ ถ้าในอนาคตต้องลบข้อมูลของหน่วยงานหนึ่งออกทั้งหมด **จะขัดกับ append-only**

⇒ **ยังไม่มีคำตัดสินเรื่องนี้** — เป็นเรื่องที่ต้องตัดสินก่อนนำไปใช้กับข้อมูลจริง
ของหน่วยงานอื่น ไม่ใช่หลังจากนั้น

### ทางลบข้อมูลทั้งหมดที่ใช้ได้จริงวันนี้

ลบโฟลเดอร์ `REDBOOK_DATA_DIR` ทั้งก้อน ⇒ ระบบสร้างใหม่เปล่า ๆ ตอนเริ่มครั้งถัดไป
🔴 วิธีนี้ลบ **audit trail ไปด้วย** — ใช้เฉพาะกับสภาพแวดล้อมทดสอบ

## 6. ระยะเวลาเก็บรักษา — **ยังไม่มีนโยบาย**

🔴 วันนี้ระบบ **ไม่ลบอะไรเลยโดยอัตโนมัติ** ยกเว้นชิ้นส่วนอัปโหลดที่ค้างเกิน 1 ชั่วโมง

การกำหนดระยะเวลาเก็บเป็นคำตัดสินที่ต้องมาจากเจ้าของงานและระเบียบของหน่วยงาน
ไม่ใช่จากผู้พัฒนา · สิ่งที่เอกสารนี้ทำได้คือ **บอกตรง ๆ ว่ายังไม่มี** เพื่อไม่ให้
ใครเข้าใจว่ามีอยู่แล้ว

| สิ่งที่ต้องตัดสิน | ใครตัดสิน |
|---|---|
| เก็บไฟล์ที่อัปโหลดไว้นานเท่าใด | เจ้าของงาน / หน่วยงาน |
| เก็บผลการรันและคำตัดสินไว้นานเท่าใด | เจ้าของงาน / อาจารย์ที่ปรึกษา |
| จะแก้ข้อขัดแย้งกับ `audit_log` แบบ append-only อย่างไร | เจ้าของงาน |
| ล็อกของแอปหมุนไฟล์ทุกเท่าใด | ผู้พัฒนาเสนอได้ แต่ต้องได้รับความเห็นชอบ |
