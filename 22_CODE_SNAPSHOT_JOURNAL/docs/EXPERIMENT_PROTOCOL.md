## 2. การแบ่งชุดข้อมูล 4 กลุ่ม

### D-SET — Development Set (ใช้สร้างและปรับกฎ)

| ขอบเขต | T1-01 ↔ T1-02 · เฉพาะ `agency_code` ∈ {21011, 21016, 01001} |
|---|---|
| ขนาด | ~24 แถวต่อฝั่ง |
| ใช้ทำอะไร | สร้าง semantic mapping · composite key · normalization · กฎ C1–C7 · ตัวอย่าง 7 กรณี |
| ข้อห้าม | **ห้ามนับเป็นผลการประเมินความถูกต้องของ engine** ทุกกรณี |

### E-SET — Evaluation Set (ปิดผนึก · blind)

| ขอบเขต | T1-01 ↔ T1-02 · **ทุกหน่วยงานที่ไม่อยู่ใน D-SET** |
|---|---|
| ขนาดโดยประมาณ | ~26,300 แถวต่อฝั่ง |
| วิธีเปิดผนึก | สคริปต์ที่ freeze แล้วเป็นผู้รันเอง ผู้พัฒนาไม่เปิดดูข้อมูลก่อนรัน |
| ตัวชี้วัดที่วัดได้จริง (ไม่ต้องมีเฉลย) | ① **รันจบโดยไม่ล้ม** ② **ตรวจซ้ำได้** — รันสองครั้งได้ `result_hash` เท่ากัน ③ **หลักฐานชี้กลับได้จริง** — สุ่ม finding มาตรวจว่าตำแหน่งที่ระบุมีค่าตามที่รายงานจริง (ตรวจด้วยเครื่อง 100% ของ finding) ④ **ยอดรวมสอดคล้อง** — ผลรวมรายหมวด C1–C7 เท่ากับจำนวนคีย์ทั้งหมด ⑤ **ไม่มีหมวดที่ระบบตัดสินว่า "ผิด" เอง** |
| ตัวชี้วัดที่ต้องใช้คน | สุ่ม 40 finding (seed ที่ผู้รับผิดชอบกำหนด) ให้มนุษย์ตรวจกับไฟล์ต้นทาง → นับว่าหลักฐานถูกต้องกี่รายการ |

**หมายเหตุสำคัญเรื่องเฉลย:** ข้อมูลจริงไม่มีเฉลยว่า "รายการนี้ควรถูกจัดหมวดใด"
E-SET จึงวัด **ความถูกต้องของหลักฐานและความทำซ้ำได้** ไม่ใช่ precision/recall
ส่วน precision/recall วัดจาก M-SET

### M-SET — Controlled Mutation Set (มีเฉลย)

| ขอบเขต | สำเนาของ T1-01 ที่ใส่การเปลี่ยนแปลงที่ทราบคำตอบล่วงหน้า |
|---|---|
| การเปลี่ยนแปลงที่จะใส่ | อย่างน้อย 7 ชนิด ตรงกับหมวด C1–C7: ลดวงเงิน · เพิ่มวงเงิน · ไม่เปลี่ยน · เพิ่มแถว · ลบแถว · ย้าย parent · ทำให้ชื่อกำกวมจนเกิด ambiguous |
| ใช้ทำอะไร | วัด precision / recall ต่อหมวด เทียบกับเฉลยที่บันทึกไว้ |
| ข้อบังคับ | ไฟล์ M-SET **ต้องมีคำว่า MUTATED ในชื่อไฟล์** · เก็บแยกโฟลเดอร์ · **ห้ามปนกับผลตรวจของข้อมูลจริงในรายงานใด ๆ** · เฉลยบันทึกเป็นไฟล์แยกพร้อม SHA-256 |

*เหตุผลที่ต้องมี M-SET: หลักการข้อ 1 ห้ามข้อมูลจำลองปนผลตรวจจริง — M-SET จึงเป็น
**การทดสอบทางเทคนิคของเครื่องมือ** ที่แยกขาดจากการทดลองกับข้อมูลจริง และต้องรายงานแยกบท/หัวข้อ*

### C-SET — Case Study Set (พรรณนา ไม่ใช่การประเมิน)

| ขอบเขต | T1-01 ↔ T1-02 · `agency_code` ∈ {21011, 21016} |
|---|---|
| ใช้ทำอะไร | รายงานสิ่งที่เกิดกับสองหน่วยงานกรณีศึกษา |
| ข้อบังคับ | ต้องระบุกำกับทุกครั้งว่า **"สไลซ์นี้ถูกใช้ในการพัฒนากฎด้วย จึงไม่ใช้เป็นหลักฐานความถูกต้องของเครื่องมือ"** · ตัวเลขต้องมาจากการรันด้วยเวอร์ชันที่ freeze แล้ว ไม่ใช่จากการสำรวจเมื่อ 27 ส.ค. |

## 3. ลำดับการรันที่เสนอ

```
freeze G1..G5
   │
   ├─ 1) รัน D-SET  → ตรวจว่ากฎทำงานตามที่ออกแบบ (ปรับกฎได้ ยังไม่ใช่ผล)
   │
   ├─ 2) freeze engine version + rule-set version  ← ห้ามแก้กฎหลังจุดนี้
   │
   ├─ 3) รัน M-SET  → precision/recall ต่อหมวด (มีเฉลย)
   │
   ├─ 4) รัน E-SET  → ทำซ้ำได้ · หลักฐานชี้กลับได้ · ยอดสอดคล้อง   ← blind
   │      แล้วสุ่ม 40 finding ให้มนุษย์ตรวจ
   │
   └─ 5) รัน C-SET  → ผลกรณีศึกษาสองหน่วยงาน (พรรณนา)
```

**ถ้าขั้นที่ 3 หรือ 4 ไม่ผ่าน** → ต้องแก้กฎ ซึ่งหมายถึง **ขึ้นเวอร์ชันใหม่และรันใหม่ทั้งหมด**
ผลของเวอร์ชันเดิมทำเครื่องหมาย `superseded` ไม่ลบทิ้ง
