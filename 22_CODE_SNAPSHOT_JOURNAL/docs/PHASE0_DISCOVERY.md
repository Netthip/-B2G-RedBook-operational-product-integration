```

                                             ▼
```

## 3. ตัวอ่าน PDF / OCR ที่มีอยู่

**ไม่มีเลย** — ค้นทั้งโครงการด้วยคำ `pdfplumber`, `pymupdf`, `fitz`, `pdfminer`, `pypdf`,
`tesseract`, `easyocr`, `paddleocr`, `ocrmypdf` แล้ว **ไม่พบการอ้างอิงแม้แต่แห่งเดียว**

สภาพเครื่องปัจจุบันที่เกี่ยวข้องกับ Phase 3:

| สิ่งที่ต้องใช้ | สถานะบนเครื่องนี้ |
|---|---|
| ไลบรารีอ่าน text layer ของ PDF | ยังไม่ติดตั้ง |
| Tesseract OCR (ไบนารี) | `where tesseract` → ไม่พบ |
| poppler-utils (`pdftoppm`) สำหรับ render หน้า PDF เป็นภาพ | ไม่พบ (ยืนยันจากการพยายามอ่าน PDF ในเครื่องแล้วล้มเหลว) |

**Phase 3 จึงต้องสร้างใหม่ทั้งหมด และต้องติดตั้งของเพิ่มก่อน** (รายละเอียดในข้อ 10)

ตรวจไฟล์เอกสารอ้างอิงที่อาจารย์ส่งให้ (เล่มของรุ่นพี่ 2 เล่ม) พบว่า:

| ไฟล์ | ขนาด | หน้า (ประมาณ) | มี text layer |
|---|---:|---:|---|
| `Thesis_Somsak_1.pdf` | 32.1 MB | ~312 | มี (พิมพ์ผ่าน Foxit PhantomPDF Printer 7.1) |
| `เล่มวิจัยระบบจองห้องประชุมออนไลน์.pdf` | 9.6 MB | ~156 | มี (Microsoft Word 2021) |

ทั้งสองเล่มเป็น**เอกสารอ้างอิงรูปแบบการเขียนเล่ม** ไม่ใช่ข้อมูลทดสอบของระบบ
และยังไม่ได้ถูกนำเข้าระบบใด ๆ

## 4. กฎตรวจยอดและกฎเปรียบเทียบเดิม

กฎที่พัฒนาแล้วและทำงานได้จริงใน `p1_numeric_validator.py`:

| รหัสเดิม | ความหมาย | เทียบกับความต้องการใหม่ |
|---|---|---|
| R1 | ยอดรวมไม่ตรง | → กฎ **Y11 / R06** (ยอดรวมไม่สัมพันธ์กับรายการย่อย) |
| R2 | จำนวน × ราคาต่อหน่วย ไม่ตรงยอด | → ยังไม่มีในชุดใหม่ ควรเพิ่มเป็นกฎภายในฝั่งเดียว |
| R3 | ข้อมูลสำคัญว่าง | → กฎ **X05** (เซลล์หรือแถวหาย) |
| R4 | หมวด/ประเภทไม่อยู่ใน mapping ตัวอย่าง | → ใกล้เคียง **Y10** (ย้ายหมวด) |
| R5 | เพิ่ม/ลดเกิน threshold | → **Y02/Y03** พร้อม threshold ที่ผู้ใช้กำหนด |
| **R6** | **มีรายการใหม่/รายการหายเทียบปีฐาน** | → **Y04/Y05** — เป็นกฎเปรียบเทียบข้ามปีตัวเดียวที่มีอยู่จริง |
| R7 | สูตรแตกต่างจาก pattern รอบข้าง | → **X02** (สูตรไม่ตรงแต่ค่าตรง) |
| R8 | ตัวเลขเป็น text หรือ format เสี่ยง | → **X08** (ตัวเลขถูกเก็บเป็นข้อความ) |

กลไกที่มีอยู่แล้วและมีคุณค่าสูง:

1. **`normalize_formula_pattern()`** — แปลงสูตรเป็น pattern เทียบข้ามแถว
   (อ้างอิงใกล้ → offset, อ้างอิงไกล → wildcard, ตัวเลข → `#`) แล้วหาเสียงข้างมาก
   ใช้จับ "เซลล์ที่สูตรแปลกกว่าเพื่อนบ้าน" ได้ดี → นำมาใช้กับ **X02** ได้เกือบทั้งดุ้น
2. **`cross_coverage`** — ตรวจว่ารายการที่เข้าเงื่อนไข (ใหม่/เกิน threshold)
   ปรากฏในบัญชีคำชี้แจงหรือไม่ → เป็นต้นแบบของ **R07/R08** (เทียบกับหลักฐานการปรับลด)
3. **ระดับความมั่นใจ 3 ชั้น** (`CONF_HIGH/MED/LOW`) พร้อมข้อความอธิบายที่มา
   → ตรงกับข้อกำหนดใหม่ที่ห้ามให้คะแนนความมั่นใจโดยไม่บอกเหตุผล
4. **ถ้อยคำที่ระวังแล้ว** — ทุก finding ลงท้ายว่า "ควรตรวจสอบ" ไม่มีคำว่า "ผิด"
   และรายงานมีบรรทัด "ทุกรายการเป็นข้อสังเกต ไม่ใช่คำตัดสิน"
   → สอดคล้องกับหลักการข้อ 2 ของ RedBook Verify โดยตรง

**สิ่งที่ยังไม่มีในกฎเดิมเลย** (ต้องสร้างใหม่ทั้งหมด):
การจับคู่รายการข้ามไฟล์ (exact/rule-based/suggested), การเทียบสองไฟล์แบบ A↔B,
การตรวจก่อน–หลังปรับลด, การตรวจโครงสร้างสมุดงาน (ชีตเพิ่ม/หาย/สลับ), การตรวจ PDF

## 7. สรุป: ส่วนที่นำกลับมาใช้ได้ / ต้องปรับ / ไม่ควรใช้

### 7.1 นำกลับมาใช้ได้ (สูง)

| รายการ | วิธีนำมาใช้ |
|---|---|
| แนวทางเปิดไฟล์ read-only (`open(path,"rb")` + ไม่มี `save()`) | **นำมาใช้แล้วใน Phase 1** พร้อมชุดทดสอบบังคับ (`test_readers_open_files_read_only`) |
| การนับสถิติเซลล์ (numeric/formula/percent/text-number/merged/hidden) | **นำมาใช้แล้วใน Phase 1** (`excel_reader.read_structure`) |
| `FormulaEvaluator` | **port ใน Phase 2** — คัดลอกมาเป็นไฟล์ใหม่ ไม่ import ของเดิม |
| `normalize_formula_pattern()` | **port ใน Phase 2** สำหรับกฎ X02 |
| แนวคิดระดับความมั่นใจ + เหตุผลกำกับ | **นำมาใช้แล้ว** (`confidence` + `confidence_basis` ที่บังคับให้มาคู่กัน) |
| ถ้อยคำที่ไม่ตัดสินถูกผิด | **นำมาใช้แล้ว** ทั้งใน Rule Catalog (`cannot_conclude`) และหน้าจอ |
| schema ของ audit record | **นำมาใช้แล้ว** ขยายเป็นตารางฐานข้อมูลพร้อมสายโซ่แฮช |
| กติกา `.gitignore` ของ repo เดิม | **นำมาใช้แล้ว** และเข้มขึ้น (กัน `.data/` ทั้งโฟลเดอร์) |

### 7.2 ต้องปรับก่อนใช้

| รายการ | ต้องปรับอะไร |
|---|---|
| mapping แบบ JSON ของ validator เดิม | เดิมผูกกับ "ไฟล์เดียว" ต้องขยายเป็น "คู่ไฟล์ A/B" และเก็บในฐานข้อมูลพร้อมเวอร์ชัน |
| `KEYWORD_PATTERNS` / `HEADER_KEYWORDS` | ใช้เป็น **ตัวช่วยเสนอ** ให้ผู้ใช้ยืนยัน ไม่ใช่ mapping อัตโนมัติ |
| กฎ R1–R8 | ต้องเขียนใหม่ให้เป็น "เทียบสองฝั่ง" ไม่ใช่ "ตรวจภายในไฟล์เดียว" |
| ระดับผล Critical/Review/Formatting/Info | แปลงเป็น severity + machine_status ตามข้อกำหนดใหม่ 7 สถานะ |

### 7.3 ไม่ควรนำมาใช้

| รายการ | เหตุผล |
|---|---|
| `P1_SAFE_LAB/engine/*` ทั้งชุด (`bis_p1_engine`, `p1_features`, `p1_sheet4`) | เป็น**ฝ่ายสร้างไฟล์** การนำเข้ามาในระบบตรวจจะละเมิดหลักการข้อ 6 โดยตรง — ถ้าใช้ตรรกะเดียวกัน ความผิดพลาดจะเกิดพร้อมกันทั้งสองฝั่งและตรวจไม่เจอ |

## 9. Architecture proposal (ที่เลือกใช้และเหตุผล)

**สรุป:** Python 3.12 + FastAPI + Jinja2 (server-rendered) + SQLite + JavaScript เท่าที่จำเป็น
ไม่มีขั้นตอน build ไม่มี npm ไม่มีบริการภายนอก

| ทางเลือก | ข้อดี | เหตุที่ไม่เลือก |
|---|---|---|
| Streamlit (ตามของเดิม) | เขียนเร็ว ใช้ engine เดิมได้ทันที | คุมหัวข้อความปลอดภัยไม่ได้ · ทำ ZAP scan ไม่มีความหมาย · UI ตามข้อกำหนด 14 หน้าจอทำไม่ได้ |
| React + API แยก | UI ยืดหยุ่นสุด | สอง runtime · พึ่ง npm (supply chain) · เพิ่มพื้นที่โจมตี · เกินจำเป็นสำหรับผู้ใช้เดี่ยว |
| **FastAPI + Jinja2 + SQLite** | ใช้ openpyxl ได้ตรง · คุม header/CSP/CSRF ได้เต็ม · ZAP scan ได้จริง · ผู้ใช้สั่งรันคำสั่งเดียว · ตรวจซ้ำได้เพราะ deterministic | — |

**ชั้นการทำงาน**

```
เบราว์เซอร์ (127.0.0.1 เท่านั้น)
   │  HTML server-rendered · Jinja2 autoescape · CSP default-src 'none'
   ▼
FastAPI (redbook/app.py)  ── SecurityMiddleware (headers) + verify_csrf ทุก POST
   ├── storage/files.py      รับไฟล์ · ตรวจ magic bytes · จำกัดขนาด · ตั้งชื่อใหม่ · SHA-256
   ├── readers/*             อ่านอย่างเดียว (Excel ตอนนี้ · PDF ใน Phase 3)
   ├── rules/*               Rule Catalog + ตัวสร้าง finding + กฎแต่ละข้อ
   └── storage/db.py         SQLite: projects · files · runs · run_rules · findings
                                     · item_matches · audit_log (append-only) · security_events
```

**ข้อบังคับเชิงสถาปัตยกรรมที่ทดสอบอัตโนมัติ** (`tests/test_architecture_separation.py`)

1. ทั้งแพ็กเกจห้ามเรียก `.save()` ใด ๆ → ไม่มีทางเขียนทับไฟล์เอกสาร
2. ห้าม import โมดูลฝั่งสร้างไฟล์ (`bis_p1_engine`, `p1_features`, `p1_sheet4`, ตัวสร้างข้อมูลเสมือน)
3. ทุก `open()` ในชั้น readers ต้องเป็นโหมดอ่าน
4. ห้าม import ไลบรารีเครือข่าย (`requests`, `httpx`, `socket`, `smtplib`, …) ในแพ็กเกจ
