## 2. ความลับ — ไม่พบ

สแกนไฟล์ที่ **track ใน git** ทั้งสอง repo ด้วยรูปแบบ
`api_key` · `secret` · `password` · `token` · `credential` · `private key` ·
`BEGIN … PRIVATE KEY` · `aws_access` · `Bearer <ยาว>` ที่ตามด้วย `=` หรือ `:`
และสตริงเอนโทรปีสูงยาว ≥ 40 อักขระ

**ไม่พบรายการที่เข้าข่ายเลย**

คำว่า `secret` ที่ปรากฏในโค้ดเป็นของ **กลไก CSRF** ซึ่งสร้าง token ขึ้นใหม่ทุก
session ด้วย `new_csrf_token()` — ไม่ใช่ค่าคงที่ที่ฝังไว้

🔴 **ข้อจำกัดของการสแกนนี้** — ตรวจเฉพาะไฟล์ที่ track อยู่ **ณ HEAD ปัจจุบัน**
**ไม่ได้ตรวจประวัติย้อนหลังทั้งสาย** · ถ้าต้องการความมั่นใจระดับนั้นต้องสแกน
`git log -p` ทั้ง repo ซึ่งยังไม่ได้ทำ

การประเมินนี้ **ต้องทำใหม่ทันที**

🔴 **แต่ยังต้องแก้** ด้วยเหตุผลสองข้อ

1. Bo สั่งให้ออกแบบการปกปิด **ก่อน** ทำ evidence export — ถ้ารอจนถึงตอนนั้น
   ค่าที่ต้องปกปิดจะกระจายไปแล้ว
2. `RUN_MANIFEST.json` (นอก git) บันทึก path **เต็มรูปแบบ** ไม่ใช่แบบย่อ

ปกปิดเมื่อค่าจะ **ออกจากเครื่อง** — manifest ที่จะแบ่งปัน · ชุดหลักฐานที่ส่งออก ·

> ### 🔁 `SUPERSEDED` — 6 กันยายน 2569
>
> ฉบับก่อนเขียนว่า *"ไม่ปกปิดใน log ระหว่างพัฒนา เพราะจะทำให้ debug ไม่ได้"*
>
> **ข้อนี้ถูกแทนที่แล้ว** — เจ้าของเลน B/Security ใส่ formatter ที่ปกปิด path
> ใน log ไปแล้วที่ `1b91353` ⇒ ข้อความเดิม **ไม่ตรงกับโค้ดปัจจุบัน**
>
> เหตุผลที่ทิศทางใหม่ถูกกว่า: log ของงานนี้อาจถูกแนบไปกับรายงานปัญหา
> หรือถูกอ่านโดยผู้ที่ไม่ควรเห็นเส้นทางแฟ้มจริง · การ debug ยังทำได้
> เพราะการปกปิด **คงความสัมพันธ์ของราก** ไว้ตามหลักข้อ 2 ด้านล่าง

### 5.2 กติกาที่เสนอ

| อินพุต | เอาต์พุต |
|---|---|
| `C:\Users\<user>\dev\redbook-verify` | `<REPO>` |
| `C:\Users\<user>\dev\redbook-verify-data\...` | `<DATA>\...` |

**หลักที่ต้องยึด**

1. ปกปิดโดย **แทนที่ด้วยสัญลักษณ์ที่คงที่** ไม่ใช่ลบทิ้ง —
   ผู้อ่านต้องยังเห็นว่าไฟล์อยู่คนละรากกันหรือรากเดียวกัน
2. 🔴 **ต้องคงความสัมพันธ์** — สอง path ที่เดิมอยู่รากเดียวกัน
   หลังปกปิดต้องยังอยู่รากเดียวกัน มิฉะนั้น provenance เสีย
3. ทำที่ **ชั้นการส่งออก** ไม่ใช่ที่ชั้นเก็บข้อมูล — ค่าจริงต้องยังอยู่ในเครื่อง
   เพื่อให้ตรวจย้อนได้
4. ปกปิด **ชื่อผู้ใช้ทุกที่ที่ปรากฏ** ไม่ใช่เฉพาะต้น path
   (เช่น ที่โผล่กลาง path ของ interpreter)

| 4 | สอง path ที่รากเดียวกัน ยังรากเดียวกันหลังปกปิด |
| 5 | manifest ที่ปกปิดแล้ว **ต้องไม่มีสตริง `Users\<ชื่อ>` เหลืออยู่เลย** |
| 6 | ค่าที่ไม่ใช่ path ต้องไม่ถูกแตะ |
