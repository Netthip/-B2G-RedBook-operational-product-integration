## ① Exact key schema

```python
KEY_VERSION   = "t1b-key-0.1.0"     # 🔒 FROZEN
KEY_FROZEN_ON = "2569-09-01"

@dataclass(frozen=True)
class T1BKey:
    # ---------- IDENTITY (7 ฟิลด์ · เข้า hash ของคีย์) ----------
    agency_code:        str   # "21000" | "21011" | "21016"
    document_level:     str   # "ministry" | "agency"      ← ห้ามจับคู่ข้ามค่า
    sheet_role:         str   # "SECTION_05" · "SECTION_07_PLAN" · "SECTION_07_PROJECT"
                              # ← จากหัวเรื่อง ไม่ใช่ชื่อชีตหรือ index
    section_title_norm: str   # ชื่อแผนงาน/โครงการ — ใช้เฉพาะกลุ่ม 7.x
                              # โครงการ = ชื่อหลัง ":" (ตัด "โครงการที่ N" ออก)
    parent_plan_norm:   str   # ชื่อแผนงานแม่ของชีตโครงการ
                              # ← กันโครงการชื่อซ้ำที่อยู่คนละแผนงาน
    plan_role:          str   # PLAN_PERSONNEL | PLAN_FUNDAMENTAL
                              # | PLAN_STRATEGIC | PLAN_INTEGRATED | NOT_APPLICABLE
    hierarchy_path:     tuple[str, ...]   # ("2", "เงินงบประมาณ") จากเลขนำหน้า
    row_label_norm:     str   # ข้อความคอลัมน์ A หลัง normalize
```

> 🔴 **การจับคู่ใช้ความเท่ากันแบบตรงตัวของคีย์เท่านั้น — ห้ามใช้ fuzzy similarity เป็น auto-match**
> ค่า similarity ใช้ได้เฉพาะเป็น *candidate ให้มนุษย์ตรวจ* ในรายงาน audit

```python
@dataclass(frozen=True)
class T1BCell:
    key:                T1BKey
    # ---------- COMPARISON ATTRIBUTES (resolve แล้วค่อยเทียบ · ไม่เข้าคีย์) ----------
    fiscal_year:        int              # 2568..2573 — จากป้าย "ปี 25xx" ไม่ใช่ตัวอักษรคอลัมน์
    declared_unit:      str              # "ล้านบาท" | "บาท" | "ร้อยละ" | "UNRESOLVED"
    value_decimal:      Decimal | None   # quantize ตามทศนิยมที่เอกสารประกาศ
    value_raw:          object           # ค่าดิบก่อน normalize — เก็บไว้ตรวจย้อน
    # ---------- PROVENANCE / LOCATION (ไม่เข้าคีย์ ไม่ใช้เทียบ) ----------
    source_file:        str
    source_sha256:      str
    sheet_name_actual:  str              # "Sheet5" / "ข้อ 5" — บันทึกไว้อ้างอิงเท่านั้น
    sheet_index_actual: int
    cell_ref:           str              # "C6"
    row_index:          int
    header_row_found:   int              # แถวหัวตารางที่ locate ได้จริง
    anchor_code:        str | None       # "sB1" / "B1" ถ้ามี
    extraction_status:  ExtractionStatus
    uncertainty:        list[str]
```

### กฎ normalize ของ `row_label_norm`

| กฎ | เหตุผลจากข้อมูลจริง |
|---|---|
| ตัดช่องว่างหน้า–หลัง | `รวมเงินนอกงบประมาณ` (FY2569) กลายเป็น ` รวมเงินนอกงบประมาณ` (FY2570) |
| ยุบช่องว่างภายในให้เหลือหนึ่ง | `ตัวชี้วัดเชิงคุณภาพ :` (1 เว้นวรรค) → `ตัวชี้วัดเชิงคุณภาพ :  ` (2 เว้นวรรค) |
| แปลง `\n` เป็นช่องว่าง | ป้ายหลายแถวมี line break กลางข้อความ |
| **ไม่** ตัดเลขนำหน้าออกจากข้อความ | เลขนำหน้าเป็นส่วนของ `hierarchy_path` ต้องแยกออกไปก่อน ไม่ใช่ทิ้ง |

## ② Field ที่เป็น IDENTITY

| ฟิลด์ | ทำไมต้องอยู่ในคีย์ |
|---|---|
| `agency_code` | คนละหน่วยงาน = คนละรายการ |
| `document_level` | 🔴 **บังคับโดย Gift ข้อ 9** — `รวมทั้งสิ้น` มีทั้งระดับกระทรวงและระดับหน่วยงาน ค่าต่างกัน 3,000 เท่า |
| `sheet_role` | บทบาทจาก `A1` — ชื่อชีตและ index ใช้ไม่ได้ (พิสูจน์แล้วใน structural map) |
| `plan_role` | แผนบุคลากร/พื้นฐาน/ยุทธศาสตร์/บูรณาการ เป็นคนละสายงบ ห้ามปน |
| `hierarchy_path` | ` เงินงบประมาณ` ปรากฏซ้ำใต้ parent หลายตัวในชีตเดียว — ข้อความอย่างเดียวไม่ unique |
| `row_label_norm` | ตัวรายการ |

## ③ Field ที่เป็น COMPARISON ATTRIBUTE

| ฟิลด์ | ทำไม**ไม่**อยู่ในคีย์ |
|---|---|
| `fiscal_year` | ถ้าอยู่ในคีย์ รายการเดียวกันคนละปีจะไม่จับคู่กัน ⇒ เทียบไม่ได้เลย · ต้อง resolve จากป้าย `ปี 25xx` แล้ว **align ก่อนเทียบ** |
| `declared_unit` | ต้องเทียบว่า**หน่วยเปลี่ยนหรือไม่** — ถ้าอยู่ในคีย์ การเปลี่ยนหน่วยจะกลายเป็น "ลบแถวเก่า + เพิ่มแถวใหม่" แทนที่จะเป็น finding ว่าหน่วยเปลี่ยน |
| `value_decimal` | ค่าที่ต้องเทียบ |
| `value_raw` | เก็บไว้ตรวจย้อนกลับ |

## ⑤ ตัวอย่างจากไฟล์จริง 5 ตัวอย่าง

**E-1 · รายการเดียวกันข้ามปี — ต้องจับคู่กันได้**

| | `T1B-X01` (FY2569) | `T1B-X04` (FY2570) |
|---|---|---|
| ชื่อชีตจริง | `Sheet5` | `Sheet5` |
| identity | `21011 / agency / SECTION_05 / NOT_APPLICABLE / () / "รวมทั้งสิ้น"` | **เหมือนกันทุกฟิลด์** |
| ตำแหน่ง | `C6` แถว 6 | `C6` แถว 6 |
| attribute | `fiscal_year=2568` · `ล้านบาท` · `53.2712` | `fiscal_year=2569` · `ล้านบาท` · `58.4401` |

⇒ คีย์ตรง · เทียบที่ `fiscal_year=2569` ซึ่งอยู่คอลัมน์ `D` ในไฟล์ 2569 แต่คอลัมน์ `C` ในไฟล์ 2570

**E-2 · ช่องว่างนำหน้าเพิ่มขึ้น — ต้องยังจับคู่ได้**

| | FY2569 | FY2570 |
|---|---|---|
| ข้อความดิบ | `'รวมเงินนอกงบประมาณ'` | `' รวมเงินนอกงบประมาณ'` ← **มีช่องว่างนำหน้า** |
| `row_label_norm` | `รวมเงินนอกงบประมาณ` | `รวมเงินนอกงบประมาณ` ✅ ตรงกัน |

**E-3 · ป้ายซ้ำใต้ parent ต่างกัน — `hierarchy_path` เป็นตัวแยก**

ใน `T1B-X01` ชีต `Sheet5` ข้อความ `' เงินงบประมาณ'` ปรากฏ **อย่างน้อย 2 ครั้ง**

| แถว | `hierarchy_path` | ค่า (ปี 2568) |
|---:|---|---:|
| 10 | `("1", "เงินงบประมาณ")` ใต้ `1. เพื่อเป็นค่าใช้จ่ายในการดำเนินการภาครัฐ` | `38.1527` |
| 15 | `("2", "เงินงบประมาณ")` ใต้ `2. การเพิ่มขีดความสามารถในการบริหารจัดการ…` | `15.1185` |

⇒ ถ้าใช้ `row_label_norm` อย่างเดียวจะจับคู่ผิดข้าม parent

**E-4 · ระดับกระทรวงกับระดับหน่วยงาน — ข้อความเหมือนกันทุกตัวอักษร**

| | `T1B-X03` (21000) | `T1B-X01` (21011) |
|---|---|---|
| `row_label_norm` | `รวมทั้งสิ้น` | `รวมทั้งสิ้น` ← **เหมือนกัน** |
| `document_level` | `ministry` | `agency` ← **ตัวแยก** |
| แถว | 4 | 6 ← ตำแหน่งต่างกัน |
| ค่า (ปี 2568) | `173390.171` | `53.2712` |

**E-5 · แถวที่มีเฉพาะระดับกระทรวง**

`- เงินรายได้` และ `- เงินกู้ต่างประเทศ ` (มีช่องว่างท้าย) ปรากฏใน `T1B-X03` แถว 7–8
แต่**ไม่มีใน `T1B-X01` เลย** ⇒ ต้องรายงานเป็น `เฉพาะฝั่งเดียว` ไม่ใช่ `เพิ่มแถว/ลบแถว`
เพราะเป็นคนละ `document_level` ที่ไม่ควรนำมาเทียบกันตั้งแต่แรก

## ⑥ คู่ที่ **ห้ามจับกัน** แม้ข้อความใกล้เคียง

| # | คู่ | เหมือนกันตรงไหน | ต้องไม่จับเพราะ |
|---:|---|---|---|
| N-1 | `รวมทั้งสิ้น` @21000 ↔ `รวมทั้งสิ้น` @21011 | ข้อความเหมือนทุกตัวอักษร | `document_level` ต่างกัน — จับแล้วจะรายงานว่ายอดกระทรวงลดลง 99.97% |
| N-2 | `' เงินงบประมาณ'` แถว 10 ↔ `' เงินงบประมาณ'` แถว 15 | ข้อความเหมือน · ชีตเดียวกัน · ไฟล์เดียวกัน | `hierarchy_path` ต่างกัน (`"1"` กับ `"2"`) |
| N-3 | `C6` ของ FY2569 ↔ `C6` ของ FY2570 | ตำแหน่งเซลล์เดียวกัน | `fiscal_year` ต่างกัน (2568 กับ 2569) — 🔴 **silent failure #1** |
| N-4 | `รวมทั้งสิ้น` (`ล้านบาท`) ↔ `- ตัวชี้วัดเชิงคุณภาพ …` (`ร้อยละ`) | ทั้งคู่เป็นตัวเลขในคอลัมน์เดียวกัน | `declared_unit` คนละชนิด — ห้ามนำ `ร้อยละ` ไปกระทบยอดเงิน |
| N-5 | `Sheet7_2` @21011 ↔ `Sheet7.2` @21016 | ชื่อชีตแทบเหมือนกัน | คนละหน่วยงาน และชื่อชีตไม่ใช่คีย์ตั้งแต่แรก |
| N-6 | `Sheet8` @21016 FY2569 (index 16) ↔ `Sheet8` @21016 FY2570 (index 18) | ชื่อชีตเหมือนกัน | ✅ **คู่นี้จับกันได้** — แต่ต้องจับด้วย `A1` role ไม่ใช่ index เพราะ index เลื่อน |

## 🔴 Silent failure ที่ **พบเพิ่ม** จากการดูข้อมูลจริงรอบนี้

Gift ระบุไว้ 8 ข้อ — Giho พบเพิ่มอีก **3 ข้อ** ที่ต้องมี test เช่นกัน

| # | อาการ | หลักฐาน |
|---|---|---|
| **9** | ช่องว่างนำหน้า/ท้ายของป้ายแถวเปลี่ยนระหว่างปี | `'รวมเงินนอกงบประมาณ'` → `' รวมเงินนอกงบประมาณ'` (`T1B-X01` → `T1B-X04` แถว 8) · `'- เงินกู้ต่างประเทศ '` มีช่องว่างท้าย |
| **10** | 🔴 **เซลล์หน่วยนับบรรจุตัวเลขแทนชื่อหน่วย** | `T1B-X04` ชีต `Sheet5` แถว 13–14 คอลัมน์ `B` = `100` (ควรเป็น `ร้อยละ`) — เป็น **data defect ในไฟล์ต้นทาง** ⇒ `unit_resolver` ต้องคืน `UNRESOLVED` และยกเป็น finding ห้ามเดา |
| **11** | จำนวนช่องว่างภายในข้อความเปลี่ยน | `ตัวชี้วัดเชิงคุณภาพ : การบริหาร…` → `ตัวชี้วัดเชิงคุณภาพ :  การบริหาร…` (เว้นวรรคสองครั้ง) |

> ข้อ **10** สำคัญเป็นพิเศษ — เป็นตัวอย่างจริงว่าไฟล์ต้นทางเองก็มีข้อบกพร่อง
> ระบบต้อง **รายงาน ไม่ใช่ซ่อมให้เงียบ ๆ**
