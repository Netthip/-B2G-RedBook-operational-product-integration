## 1. สิ่งที่โปรโตคอลนี้วัด และไม่วัด

| วัด | ไม่วัด |
|---|---|
| ความสามารถของ detector ในการ **พบ** ข้อบกพร่องที่ถูกใส่ไว้ | ความพึงพอใจของผู้ใช้ |
| ความสามารถในการ **ระบุตำแหน่งและชนิด** ให้ถูก | เวลาที่ประหยัดได้ |
| อัตราการเตือนผิดบนแฟ้มที่สะอาด | ความถูกต้องของตัวเลขในเอกสารต้นทาง |
| ความคงเส้นคงวาของผลเมื่อรันซ้ำ | ความปลอดภัยของระบบ (แยกไปหมวด security) |

### 🔴 ข้อห้ามที่หนักที่สุด — คำที่ห้ามใช้สลับกัน

**การรันซ้ำด้วย input เดิม วัด `ความคงเส้นคงวา / ทำซ้ำได้` ไม่ใช่ `ความแม่นยำ`**

⇒ ห้ามเขียนว่า *"รันซ้ำได้ผลเท่าเดิม จึงแม่นยำ"* เด็ดขาด
⇒ ตัวเลขความถูกต้องมาจาก **การเทียบกับเฉลยที่ปิดไว้เท่านั้น**

และเนื่องจากในงานตรวจสอบเอกสาร **true negative มีจำนวนมหาศาล** (เซลล์ที่ไม่มีข้อบกพร่อง)
🔴 **ห้ามรายงาน `accuracy` ดิบ** เพราะจะสูงเกือบ 100% เสมอโดยไม่มีความหมาย
เกณฑ์ `≥90%` ที่จะประกาศต้อง **ระบุว่าเป็นตัวชี้วัดใด** เสมอ

## 2. บทบาทที่ต้องแยกจากกัน — ข้อกำหนดเชิงระเบียบวิธี

| บทบาท | หน้าที่ | 🔴 ห้าม |
|---|---|---|
| **ผู้สร้างชุดทดสอบ** | สร้างแฟ้มสะอาด · ใส่ข้อบกพร่อง · เขียนเฉลย | ห้ามแตะโค้ด detector · ห้ามดูผลก่อนปิดผนึก |
| **ผู้พัฒนา detector** | พัฒนาและตรึงเวอร์ชัน | 🔴 **ห้ามเห็นเฉลย** · ห้ามเห็นรายการข้อบกพร่อง |
| **ผู้ให้คะแนน** | เทียบผลที่ปิดผนึกกับเฉลย | ห้ามแก้ผลหรือเฉลย |

🔴 **ข้อห้ามที่ Gift ระบุตรง ๆ** — ห้ามให้ตัวแทนเดียวกัน *สร้างข้อบกพร่อง* →
*ดูเฉลย* → *ปรับ detector กับเคสนั้น* แล้วเรียกผลว่า **blind**

**สถานะปัจจุบัน:** 🔴 ยังไม่มีการแยกบทบาทนี้ — **เป็นคำตัดสินที่ต้องขอจาก Gift**
ทางเลือกที่เห็น: (ก) Gift เป็นผู้สร้างชุดทดสอบเอง · (ข) ให้ agent คนละตัวที่ไม่มีสิทธิ์
อ่านโค้ด detector เป็นผู้สร้าง · (ค) สร้างล่วงหน้าแล้วปิดผนึกก่อนพัฒนา detector รอบถัดไป

## 4. บัญชีชนิดข้อบกพร่องที่เสนอ — **ยังไม่สร้างจริง**

> 🔴 ตารางนี้เป็น **บัญชีชนิด** ไม่ใช่เฉลย · ไม่มีที่ใดในเอกสารนี้ระบุว่า
> ข้อบกพร่องตัวใดจะถูกใส่ที่ตำแหน่งใดหรือกี่ตัว

### 4.1 กลุ่ม `V` — ค่าและยอด

| รหัส | ชนิด | ทำไมจึงสำคัญกับงานปรับลดงบประมาณ |
|---|---|---|
| `V-01` | ยอดของแถวลูกเปลี่ยน แต่ยอดแม่ไม่เปลี่ยนตาม | รูปแบบพบบ่อยที่สุดของการปรับลดที่ทำไม่ครบ |
| `V-02` | ยอดแม่เปลี่ยน แต่ลูกไม่เปลี่ยน | ทิศตรงข้ามของ `V-01` |
| `V-03` | ผลรวมรายหมวดไม่เท่าคอลัมน์ `รวม` | ตรงกับกฎ `CATEGORY_SUBTOTALS_TO_TOTAL` |
| `V-04` | สลับหลักพัน/ล้าน (ผิดหน่วยหนึ่งขั้น) | ความผิดที่ดู "สมเหตุสมผล" ที่สุด |

| `V-07` | ยอดปีอนาคต/ภาระผูกพันไม่สอดคล้องกับปีฐาน | ตรงกับข้อกำหนดในหัวข้อกระทู้ |

### 4.2 กลุ่ม `S` — โครงสร้างและความสอดคล้องข้ามชีต

| รหัส | ชนิด |
|---|---|

| `S-03` | แถวถูกลบออกจากฉบับหลัง โดยยอดรวมไม่ถูกปรับ |
| `S-04` | แถวถูกเพิ่มเข้ามาโดยไม่มีที่มา |
| `S-05` | ลำดับโครงการเปลี่ยน แต่เนื้อหาเดิม (ต้องไม่ถือเป็นข้อผิดพลาด) |
| `S-06` | ชื่อแผนงาน/ผลผลิตเปลี่ยน แต่เป็นรายการเดียวกัน |

### 4.3 กลุ่ม `T` — ข้อความและตัวชี้วัด

| รหัส | ชนิด |

| `T-03` | ป้ายแถวเปลี่ยนเฉพาะช่องว่าง/เครื่องหมาย (ต้องไม่ถือเป็นข้อผิดพลาด) |

### 4.4 กลุ่ม `F` — สูตรและการแปลงค่า

| รหัส | ชนิด | หมายเหตุ |
|---|---|---|
| `F-01` | ค่าที่ควรมาจากสูตรถูกพิมพ์ทับด้วยมือ | 🔴 ตรวจไม่ได้ด้วยความสามารถวันนี้ (`A3`) |

### 4.5 กลุ่ม `N` — ตัวล่อที่ **ต้องไม่** ถูกรายงานว่าเป็นข้อผิดพลาด

🔴 **บังคับต้องมี** — ถ้าชุดทดสอบมีแต่ข้อบกพร่องจริง จะวัด false positive ไม่ได้เลย

| รหัส | ชนิด |
|---|---|
| `N-01` | เปลี่ยนเฉพาะรูปแบบการแสดงผล ค่าคงเดิม |
| `N-02` | ช่องว่างนำหน้า/ตามหลังเปลี่ยน |
| `N-03` | เรียงลำดับแถวใหม่โดยเนื้อหาเดิม |
| `N-04` | เพิ่มชีตประกอบที่ไม่เกี่ยวกับผลตรวจ |
| `N-05` | เปลี่ยนชื่อชีตโดยหัวเรื่องเดิม |

**สถานะความสามารถวันนี้ (ประกาศไว้ล่วงหน้า ห้ามแก้ย้อนหลัง)**

* คาดว่า **ตรวจได้**: `V-01`..`V-03` · `V-06` · `S-01`(บางส่วน) · `S-03` · `S-04` · `T-01`
* คาดว่า **ตรวจไม่ได้**: `F-01` `F-02` `F-04` · `S-02` ข้ามชีต · `V-07`
* คาดว่า **ต้องไม่แจ้ง**: `N-01`..`N-05` · `S-05` · `T-03`

🔴 การประกาศล่วงหน้านี้มีไว้เพื่อกันการอธิบายผลย้อนหลัง — **ถ้าผลจริงต่างจากนี้
ต้องรายงานว่าต่าง ไม่ใช่แก้ข้อความนี้**

## 5. ตัวชี้วัดและตัวหาร

| ตัวชี้วัด | นิยาม |
|---|---|
| `TP` | ข้อบกพร่องที่ใส่ไว้ และ detector รายงานถูก **ทั้งตำแหน่งและชนิด** |
| `TP-loc` | รายงานตำแหน่งถูก แต่ชนิดผิด — **นับแยก ห้ามรวมกับ `TP`** |
| `FP` | รายงานที่ไม่ตรงกับข้อบกพร่องใดในเฉลย |
| `FN` | ข้อบกพร่องในเฉลยที่ไม่มีรายงานใดตรง |
| `precision` | `TP / (TP + FP)` |
| `recall` | `TP / (TP + FN)` |
| `F1` | ค่าเฉลี่ยฮาร์มอนิกของสองตัวข้างบน |

**ตัวหารที่ต้องประกาศทุกครั้ง**

* จำนวนข้อบกพร่องที่ใส่ทั้งหมด แยกรายชนิด
* จำนวนรายการที่ **อยู่นอกความสามารถที่ประกาศไว้** — รายงานแยก ห้ามนับเป็น `FN` เงียบ ๆ
* จำนวนรายการที่ระบบส่งเข้า **คิวมนุษย์** — 🔴 ต้องตัดสินล่วงหน้าว่านับอย่างไร

🔴 **คำตัดสินที่ต้องขอจาก Gift ก่อนรัน** — รายการที่ระบบไม่ฟันธงแต่ **ส่งให้คนตรวจ**
ถือเป็นอะไร ทางเลือก: (ก) `TP` เพราะระบบชี้จุดถูก · (ข) ไม่นับทั้ง `TP`/`FP`
แต่รายงานเป็นชั้นที่สาม · (ค) `FP` เพราะเพิ่มภาระคน
**ต้องตัดสินก่อนเห็นผล** มิฉะนั้นการเลือกทีหลังคือการเลือกให้ตัวเลขสวย
