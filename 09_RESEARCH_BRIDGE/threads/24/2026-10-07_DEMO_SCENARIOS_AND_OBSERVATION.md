# #24 — สถานการณ์สาธิต · แบบสังเกตเชิงก่อรูป (formative)

**ผู้ร่าง:** Giho · 7 ต.ค. 2569 · **สถานะ:** `READY FOR REVIEW`
**ผู้ใช้เป้าหมาย:** อาจารย์ผู้ประเมิน · ผู้ใช้ภายใน · ผู้ตรวจเอกสารงบประมาณ

> 🔴 ใช้กับ**โหมดสาธิต**เท่านั้น — ทะเบียนเล่มเป็นเอกสารที่เผยแพร่ต่อสาธารณะแล้ว
> ส่วนสมุดงานที่นำมาเทียบเป็น**ข้อมูลสังเคราะห์ 100%** ผลตรวจที่เห็นจึงห้ามรายงานว่าเป็นข้อผิดพลาดของเล่มจริง
>
> 🔴 การให้ผู้ใช้ 1–3 คนลองกด = **formative walkthrough** เพื่อหาจุดติดและปรับแบบ
> **ไม่ใช่** การประเมิน usability และห้ามสรุปเป็นสถิติ (ดู §4)

---

## 0. เตรียมก่อนเปิดให้ลอง (ผู้จัด = กิ๊ฟ)

1. เปิดโหมดสาธิตแบบล้างข้อมูลเดิม (คำสั่งเดียวใน repo โค้ด · `demo_launch --reset`)
2. เปิดเบราว์เซอร์ที่หน้าแรกของระบบ · ปิดแท็บอื่น · ขยายหน้าต่างเต็มจอ
3. บอกผู้ลอง: "ระบบนี้ยังเป็นต้นแบบ เรากำลังหาจุดที่ใช้ยาก ไม่ได้ทดสอบตัวท่าน ติดตรงไหนพูดออกมาได้เลย"
4. ผู้จัด**ไม่ชี้ทาง**ระหว่างทำ — ถ้าผู้ลองถาม ให้จดว่าถาม แล้วตอบสั้นที่สุด
5. ตรวจให้แน่ใจว่าเห็นป้าย "โหมดสาธิต · ข้อมูลสังเคราะห์" ที่เมนูซ้าย

ตรวจเส้นทางล่วงหน้าได้ด้วย `journey_smoke` (เดินทั้งสาม scenario อัตโนมัติ คืน exit ≠ 0 ถ้าขั้นใดไม่ผ่าน)
ผลล่าสุด 7 ต.ค. 2569: **ผ่านครบ 22 ข้อตรวจ** บนเบราว์เซอร์จริง

## Scenario 1 — หาเล่มของปีหนึ่งและหน่วยงานหนึ่ง แล้วเปิด PDF

| | |
|---|---|
| **เหมาะกับ** | ผู้ใช้ภายใน · อาจารย์ (ใช้เปิดเรื่อง) |
| **สถานะเริ่ม** | หน้าแรก · ยังไม่ได้ค้นอะไร |
| **งานที่ให้ทำ** | "ช่วยหาเล่มงบประมาณ**ปี 2569** ของ**กระทรวงสาธารณสุข** แล้วเปิดไฟล์ PDF ของเล่มนั้น" |
| **เส้นทางที่คาด** | พิมพ์ "สาธารณสุข" ในช่องค้นหา → กด "พ.ศ. 2569" → (กดเปิด PDF จากการ์ด **หรือ** เข้าหน้ารายละเอียดแล้วกด "เปิด PDF ต้นทาง") |
| **ผลที่คาด** | แท็บใหม่เปิด PDF จากเว็บไซต์สำนักงบประมาณ · หน้าระบบยังอยู่ในแท็บเดิม |
| **เส้นทางอื่นที่ถือว่าสำเร็จ** | กดปี 2569 ก่อนแล้วค้น · ใช้ตัวเลือกกระทรวง · ค้นว่า "สาธารณสุข 69" |

**จุดสังเกต**
- เริ่มจากช่องค้นหา หรือมองหาเมนูก่อน?
- อ่านการ์ดแล้วรู้ไหมว่าเล่มไหนคือปี 2569 **โดยไม่ต้องเปิด**
- เข้าใจไหมว่า "เล่ม 11 · ฉบับที่ 3" บนปกคืออะไร
- เห็นปุ่ม "เปิด PDF" ไหม · แปลกใจไหมที่เปิดในแท็บใหม่
- ตัวเลขข้างปี/ประเภท ช่วยหรือรบกวน

## Scenario 2 — เลือกเอกสารสองฉบับเพื่อนำไปตรวจเปรียบเทียบ

| | |
|---|---|
| **เหมาะกับ** | ผู้ตรวจเอกสาร · ผู้ใช้ภายใน |
| **สถานะเริ่ม** | หน้ารายละเอียดเล่ม "กระทรวงสาธารณสุข ปี 2569" (ต่อจาก Scenario 1 ได้) |
| **งานที่ให้ทำ** | "อยากตรวจว่าเล่มนี้ปี 2569 ต่างจากปี 2570 อย่างไร ช่วยตั้งงานตรวจให้หน่อย" |
| **เส้นทางที่คาด** | "ใช้เล่มนี้ในการตรวจ" → เลือกการ์ดปี 2570 ใน "คู่ที่แนะนำ" → ดูชื่องานที่ตั้งให้ → "เริ่มตรวจ — ไปขั้นใส่ไฟล์" |
| **ทางลัดที่ถือว่าสำเร็จ** | ในหน้ารายละเอียด ส่วน "เล่มเดียวกันในปีอื่น" กด "เทียบกับปี 2569" จากปี 2570 · หรือในคลังเล่มมุมมอง "ตามเล่ม" กด "เทียบ 2569 กับ 2570" |
| **ผลที่คาด** | หน้างานตรวจ (ขั้น 2) แสดง "เล่มอ้างอิงของงานนี้" ทั้งสองฝั่ง · ฝั่ง A = 2569 · แถบขั้นตอนชี้ขั้น 2 |

**จุดสังเกต**
- เข้าใจไหมว่า "ใช้เล่มนี้ในการตรวจ" จะพาไปไหน
- เห็นช่อง A/B แล้วรู้ไหมว่ายังขาดฉบับไหน
- สังเกตไหมว่าระบบจัดปีเก่าไว้ฝั่ง A ให้
- อ่านกล่อง "สิ่งที่ระบบเทียบจริง" แล้วเข้าใจไหมว่าต้องใส่ไฟล์ Excel ต่อ (**จุดเสี่ยงสับสนที่สุด**)
- คาดว่าระบบจะอ่าน PDF เองหรือไม่ — ถ้าใช่ จดคำพูดไว้ (ผูกกับคำตัดสิน D3)

## Scenario 3 — ดู finding หนึ่งรายการ เปิดหลักฐาน ตัดสิน และไปถึง preflight

| | |
|---|---|
| **เหมาะกับ** | ผู้ตรวจ · อาจารย์ (ส่วนแสดงคุณค่าเชิงวิจัย) |
| **สถานะเริ่ม** | หน้างานตรวจจาก Scenario 2 · ผู้จัดกด "ใส่คู่ไฟล์สาธิต (สังเคราะห์)" ให้ แล้วกด "เปรียบเทียบเนื้อในสมุดงาน" |
| **งานที่ให้ทำ** | "เลือกดูรายการหนึ่งรายการ ดูว่าหลักฐานอยู่ตรงไหน ตัดสินรายการนั้น แล้วดูว่าตอนนี้ส่งออกได้หรือยัง เพราะอะไร" |
| **เส้นทางที่คาด** | สรุปความต่าง → คิวพิจารณา (แถบขั้นตอนข้อ 4) → "ดู" หนึ่งรายการ → อ่านค่าที่นำมาเทียบ + ตำแหน่งหลักฐาน (+ เปิดเล่มอ้างอิงทางการได้) → เลือกคำตัดสิน → บันทึก → Preflight (แถบขั้นตอนข้อ 5) |
| **ผลที่คาด** | ผู้ลองอธิบายได้ว่า "ยังส่งออกไม่ได้ เพราะยังเหลือรายการที่ไม่ได้ตัดสิน และต้องรับทราบรายการที่ระบบอ่านไม่ครบ" โดยอ่านจากหน้า Preflight |

**จุดสังเกต**
- หาทางจากสรุปไปคิวเองได้ไหม (ใช้แถบขั้นตอนหรือเมนูซ้าย)
- เข้าใจ "ฉบับตั้งต้น / ฉบับปัจจุบัน / ผลต่าง" ไหม
- รู้ไหมว่าเหตุผลบังคับกรอกเมื่อไร
- อ่านด่าน Preflight แล้วบอก "ทางแก้" ได้ไหม · สีแดง/เขียวช่วยไหม

## 2. หลังจบแต่ละคน (ไม่เกิน 3 คำถาม)

1. ส่วนไหนใช้ง่ายที่สุด
2. ส่วนไหนทำให้ลังเลหรือต้องหยุดคิด
3. ถ้าจะใช้กับงานจริง ขาดอะไร

## 3. การนำผลไปใช้

- แปลงแต่ละจุดติดเป็นรายการ "ปัญหา → หน้าจอ → ความรุนแรง (ติดจนทำต่อไม่ได้ / ช้าลง / เล็กน้อย)"
- ปัญหาที่เจอ ≥ 2 คน หรือ "ติดจนทำต่อไม่ได้" แม้คนเดียว → ปรับแบบก่อนรอบถัดไป
- บันทึกลง evidence map แถว `E-FORM` (formative) เท่านั้น

## 4. ข้อห้ามในการอ้าง

| ห้ามเขียน | เขียนได้ |
|---|---|
| "ผู้ใช้หาเล่มได้เร็วขึ้น X%" | "ในการเดินทดสอบเชิงก่อรูปกับผู้ใช้ N คน พบจุดติดดังนี้ … และปรับแบบดังนี้ …" |
| "ระบบใช้งานง่าย" / "ผ่าน usability" | "ระบบรองรับการหาเล่มย้อนหลัง 3 ปีจากแหล่งทางการ (ยืนยันด้วยการเดินทดสอบอัตโนมัติ)" |
| "ผู้ใช้พึงพอใจ" | อ้างคำพูดผู้ลองตรง ๆ โดยไม่ระบุตัวตน พร้อมบอกว่าเป็นความเห็นเชิงก่อรูป |
| อ้างจำนวนคลิกเป็นผลการประเมิน | อ้างจำนวนคลิกเป็น "เส้นทางที่ออกแบบไว้" (design rationale) |

การประเมิน usability/effectiveness ขั้นสุดท้าย ต้องมี protocol ที่ประกาศล่วงหน้า
(งาน จำนวนผู้ร่วม เกณฑ์สำเร็จ เครื่องมือวัด) และผ่านประเด็นจริยธรรม/ความยินยอมตามที่กิ๊ฟตัดสิน — ไม่อยู่ในใบนี้
