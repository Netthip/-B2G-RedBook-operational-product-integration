## 1. ขอบเขต → ท่าที → ตัวชี้วัด → ตัวหาร (ตารางเดียว ไม่ตัดชนิดใดออกเงียบ ๆ)

⇒ ชนิดที่ต้องอาศัยความสามารถนั้น **ยังอยู่ในตัวหาร** และคาดการณ์ล่วงหน้าว่าผลจะต่ำ

ห้ามรายงานเป็น 0 หรือ 1 · ห้ามตัดแถวนั้นออกจากตาราง · ห้ามเลือกชุดใหม่เพื่อให้มีกรณีบวก

อื่น ๆ ที่รายงานค่าจริงโดยไม่ตั้งเป้า: ความครอบคลุมเซลล์ที่เปลี่ยน · ภาระคนตรวจ · ผลรายหน่วยงานแยก + รวม

## 2. ชนิดคู่เอกสาร — ตอบวัตถุประสงค์ต่างกัน

| | คู่ก่อน–หลังปรับลด (ปีเดียวกัน) | คู่ข้ามปี (ร่างปีก่อน ↔ ร่างปีนี้) |
|---|---|---|
| ตอบคำถาม | ระบบช่วยตรวจ **ว่าการปรับลดถูกสะท้อนครบและถูกที่** ไหม — งานจริงของ "คาดแดง" | ระบบรับมือ **การเปลี่ยนตามธรรมชาติข้ามปี** ได้ไหม |
| ลักษณะการเปลี่ยน | น้อย กระจุก ส่วนใหญ่ยอดลด + ยอดที่ไหลตาม | มาก หลากหลาย ส่วนใหญ่ตั้งใจ |
| ใกล้กรณี formative | ใกล้มาก | ห่างกว่า |
| ภาระทำเฉลย | ต่ำกว่า | สูงกว่ามาก |
| ไฟล์สาธารณะ | **ต้องยืนยัน** ว่าฉบับหลังปรับลดรายหน่วยงานเผยแพร่ที่ใด | มีแน่นอนทั้งสองปี |

**ข้อเสนอ:** ชนิดหลักควรตรงวัตถุประสงค์ของงาน (ก่อน–หลังปรับลด) ถ้าหาไฟล์สาธารณะได้ · คู่ข้ามปีเป็นชุดเสริม · **ห้ามรวมคะแนนสองชนิดเป็นตัวเลขเดียว**

## 3. จำนวนหน่วยงาน — ข้อเสนอ ไม่ใช่ขั้นต่ำทั่วไป

**ข้อเสนอ: 3 หน่วยงาน** ต่างขนาด/ต่างชนิด (องค์การมหาชนขนาดเล็ก + ส่วนราชการ) เพราะเอนจินพัฒนาบนองค์การมหาชนขนาดเล็กเท่านั้น
เหตุผล: หนึ่งหน่วยรายงานได้แค่กรณีศึกษา · สามหน่วยพอเห็นความแปรผันระหว่างหน่วย · เพดานจริงคือเวลาทำเฉลยของกิ๊ฟ (ถ้าไม่พอ ใช้ 2 และประกาศเป็นข้อจำกัด)
ตัวเลขนี้ **ไม่ใช่เกณฑ์ทางสถิติ** และรอกิ๊ฟตัดสิน · หน่วยที่เหลือเก็บไว้รอบถัดไป (ชุดประเมินใช้ได้ครั้งเดียว)

## 5. ขั้นตอน + นโยบาย unlock / log / retry (ตรึงพร้อมแผน)

1. Bo ตรวจรับด่าน #21 และแผนนี้ · ตรึงเอนจินด้วย tag ใหม่ + แฮช source · commit แผนนี้ — **ก่อนเลือกชุด**
2. กิ๊ฟเลือกจากชื่อไฟล์/ทะเบียน (หรือสุ่มแบบประกาศ seed — กิ๊ฟเลือกวิธี) · บันทึกนอก repo สาธารณะ
3. ปิดผนึก: ย้ายไฟล์เข้า `FINAL_HOLDOUT_SEALED` · manifest แฮช · ลบสำเนาที่แตกค้างไว้เดิม
4. กิ๊ฟทำเฉลยตาม custody (#11) · ผนึกเฉลยก่อนรัน
5. **unlock** — record เดียว · `approved_by` = กิ๊ฟ · ระบุแฮชของไฟล์ที่จะรันครบและเท่านั้น · `engine_ref` = tag ที่ตรึง · สร้างหลังผนึกเฉลยแล้วเท่านั้น · ถอนทันทีหลังรันเสร็จ
6. **log** — access log ของด่านเก็บทั้งไฟล์ · รายงานจำนวนครั้งที่เปิด + แฮชของไฟล์ log ในผลประเมิน · เปิดเกินที่วางแผน = ต้องรายงาน
7. **retry** — รันครั้งเดียว · ถ้า **ล้มทางเทคนิคจนไม่มีผลลัพธ์** รันซ้ำได้ด้วย tag เดิมเท่านั้นและบันทึกทุกครั้ง · ถ้า **มีผลลัพธ์แล้ว ห้ามรันซ้ำ** · แก้เอนจินหลังเห็นผล ⇒ ผลเป็น development iteration และต้องใช้ชุดใหม่
8. ผนึกผล (เวลา + แฮช) ก่อนเปิดเฉลย · คิดคะแนนตามข้อ 1 · ห้ามแก้ผลหรือเอนจินย้อนหลัง
