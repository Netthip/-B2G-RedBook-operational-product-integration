## 3. ทำเสร็จ รอ Bo ตรวจ

### #7 โต๊ะตรวจคาดแดง — เมนู · ขั้นตอน 1–6 · ด่านก่อนส่งออก

เดินได้ครบหนึ่งรอบแล้ว: ใส่ไฟล์สองฉบับ → หาความต่าง → พิจารณา → ตรวจก่อนส่งออก → ส่งออก

* เมนูซ้ายคงที่ 7 รายการ · เดิมหน้าคิว หน้าส่งออก และ Audit ไปถึงได้ด้วยการพิมพ์ URL เท่านั้น
* แถบขั้นตอน 1–6 บอกตำแหน่งปัจจุบันและงานที่ยังค้าง · แดชบอร์ดเปิดรอบเดิมกลับมาได้
* **ด่านก่อนส่งออกเป็นด่านจริงฝั่งเซิร์ฟเวอร์** ประเมินใหม่จากของจริงก่อนเขียนไฟล์ทุกครั้ง
  ไม่ผ่านคืน `409` + บันทึกเหตุการณ์ + **ไม่เขียนไฟล์ใดเลย**
* ด่านห้าข้อ: รายการที่ยังไม่ตัดสิน · ยอดกระทบไม่ลงตัว · รายการที่ระบบอ่านไม่ครบและยังไม่รับทราบ ·
  ยังยืนยันไม่ได้ว่าเป็นหน่วยงานเดียวกัน · ไม่มีรายการที่ยืนยันให้ส่งออก
* การรับทราบรายการที่อ่านไม่ครบ **ผูกกับชุดรายการด้วยแฮช** ชุดเปลี่ยนเมื่อใดใช้ไม่ได้อีกทันที

🔴 **ข้อบกพร่องที่พบระหว่างทำ และแก้แล้ว** — นโยบาย referrer ที่เข้มงวดเกินไป
ทำให้เบราว์เซอร์ส่งค่า origin เป็น `null` มากับการส่งแบบฟอร์มแม้เป็น same-origin
⇒ ด่าน CSRF ปฏิเสธทุกคำขอ ⇒ **แบบฟอร์มทั้งระบบใช้งานไม่ได้บนเบราว์เซอร์จริง**
ชุดทดสอบระดับ HTTP จับไม่ได้เลยเพราะไม่เคยส่งหัวนี้มา
แก้พร้อมเทสต์กันถอยหลังสามข้อ รวมข้อที่ยืนยันว่าคำขอข้ามไซต์จริงยังถูกปฏิเสธ

🔑 บทเรียน: **เทสต์ระดับ HTTP ไม่แทนเบราว์เซอร์จริง**

### #9 ข้อมูลสาธิตสังเคราะห์ + หลักฐานบนเบราว์เซอร์จริง

* คู่สมุดงานสังเคราะห์ 100% ให้ข้อสังเกต 9 ชนิด · ตัวสร้างไฟล์อยู่ **นอกแพ็กเกจฝ่ายตรวจ**
  ตามด่านสถาปัตยกรรมเดิมที่ห้ามฝ่ายตรวจมีโค้ดสร้างเอกสาร
* โหมดสาธิตเปิดด้วยคำสั่งเดียว เขียนข้อมูลลงโฟลเดอร์แยกจากงานจริง
* browser smoke test เดินครบทั้งหกขั้นบนเบราว์เซอร์จริง เก็บภาพทุกหน้าจอ
  คืน exit code ไม่ใช่ศูนย์เมื่อขั้นใดไม่เป็นไปตามที่ควรเป็น

## 4. ทำเสร็จบางส่วน — ติดที่การประกาศของคน

### #5 สัญญาการให้คะแนนสามชั้น + ตารางท่าทีที่ประกาศล่วงหน้า

ตารางครบ 25 ชนิดอยู่ในโค้ดแล้ว พร้อมด่านบังคับ · **stratum มาจากท่าทีเสมอ ตั้งแยกไม่ได้**
⇒ ไม่มีทางเกิดคู่ที่ขัดกันเอง เช่นชนิดที่ประกาศว่าตรวจไม่ได้ไปนั่งใน stratum ที่มีเกณฑ์ผ่าน

ตัวล่อไปอยู่กองควบคุมเชิงลบ ไม่อยู่ในตัวหารของ stratum ใด ·
ด่านตรวจเฉลยกันการย้ายชนิดข้าม stratum หลังเห็นผล ด้วยโค้ด

🔴 **ช่องว่างสองข้อที่พบตอนประกอบตาราง — ไม่เติมให้เอง**

1. **ห้าชนิดที่โปรโตคอลไม่เคยประกาศท่าทีไว้** อยู่ในบัญชีหมวด 4 แต่ไม่ปรากฏใน
   บรรทัดสถานะความสามารถทั้งสามกลุ่ม ⇒ ด่านปฏิเสธการสร้างเฉลย
2. **ไม่มีชนิดใดถูกประกาศว่า "คาดว่าควรส่งต่อ" เลย** ทั้งที่ §5.7 นิยาม stratum หลัก
   ว่ารวมท่าทีนี้ด้วย ⇒ **วัด referral recall ไม่ได้** ซึ่งเป็นหนึ่งในสามชั้นของการให้คะแนน

การเติมท่าทีย้อนหลังจะทำลายคุณสมบัติ "ประกาศล่วงหน้า" ทั้งหมด จึงต้องให้คนประกาศ

## 7. 🔴 สองเรื่องเชิงกระบวนการที่ขอให้ทราบ

**① มีสองเซสชันทำงานพร้อมกันในวันเดียว และทำงานซ้ำกันจริง**

วันนี้ #6 ข้อ 2–3 ถูกทำ **สองรอบโดยสองเซสชัน** โดยไม่รู้ตัว
`frozen.txt` ของทั้งสองรอบแฮชตรงกันทุกไบต์ ⇒ ไม่มีผลขัดกัน แต่เสียแรงซ้ำ
และเกือบเกิดหลักฐานสองชุดที่ชี้คนละที่

รวบให้เหลือชุดเดียวแล้ว คงชุดที่อยู่ใต้ `threads/` ตามกติกาใหม่
และต่อท้ายคำแก้ไขแบบ append-only หนึ่งจุด (ข้อความเดิมไม่แก้)

นอกจากนี้ยังมีความเห็นต่างกัน: อีกเซสชันเลือก **ไม่ push** การแก้เอกสารเพราะมี
hit เดิมค้างอยู่ในไฟล์ · ผมเลือก **push** เพราะบรรทัดที่เพิ่มใหม่ผ่านสะอาด
และ hit เดิมเผยแพร่ไปก่อนหน้านี้แล้ว การลบตอนนี้ไม่ทำให้หายจากประวัติ
⇒ ขอให้ตัดสินว่าแนวไหนเป็นมาตรฐาน

**② ตัวตรวจการรั่วไหลเคยเป็น fail-open**

ถ้าโหลดไฟล์รูปแบบไม่ได้ จะไม่มีรูปแบบให้ตรวจเลยแต่ยังรายงานว่าผ่าน
⇒ ผล "0 hit" ก่อนหน้านี้ **ใช้เป็นใบอนุญาตเผยแพร่เดี่ยว ๆ ไม่ได้**
แก้แล้วในวันเดียวกัน (#13 BLOCKER 2) — ตั้งแต่นี้ไปควรยืนยัน self-test ทุกครั้งที่อ้างผล
