| ชั้น | คู่เอกสาร | ตอบคำถาม | เกณฑ์ผ่าน |

| `EXPLORATORY` | ข้ามปี: ร่างปีก่อน ↔ ร่างปีที่เลือก ของ **หน่วยงานชุดเดียวกัน** | ระบบรับมือการเปลี่ยนตามธรรมชาติข้ามปีได้ไหม | **ไม่มี** — รายงานเชิงพรรณนาเท่านั้น |

- การเปิดเผย: ร่าง พ.ร.บ. และ พ.ร.บ. เป็นเอกสารที่เผยแพร่ต่อสาธารณะทั้งคู่ ⇒ ผลต่างร่าง→พ.ร.บ. เปิดเผยได้ · เอกสารขั้นคำขอ/ภายใน **ห้ามใช้**

- รายงานค่าจริงโดยไม่ตั้งเป้า: ความครอบคลุมเซลล์ที่เปลี่ยน · ภาระคนตรวจ (ถ้า engine tag มีชั้นแบ่งกองของ #26) · ผลรายหน่วยงานแยก + รวมภายในชั้นเดียวกัน
- ไม่มีเกณฑ์ตัวเลขอื่น (เช่น ≥90%) — เพิ่มเกณฑ์ = ขึ้นรุ่น และทำได้ก่อนผนึกเฉลยเท่านั้น

## 4. วิธีเลือก — stratified random จาก metadata

### 4.1 ชั้น — ยืนยันจาก metadata ทางการพร้อม provenance

| ค่า | ความหมาย |
|---|---|
| `S-GOV` | ส่วนราชการ |
| `S-PO` | องค์การมหาชน / หน่วยงานของรัฐที่ไม่ใช่ส่วนราชการ |
| `TYPE_UNVERIFIED` | ยังยืนยันประเภทจากแหล่งทางการสาธารณะไม่ได้ |

- `agency_type` ยืนยันโดย #27/ทะเบียน จาก **metadata ทางการสาธารณะ** และบันทึก provenance (แหล่ง · วันที่ตรวจ) ทุกหน่วย — **ไม่ใช้ความจำหรือรายชื่อร่าง**
- ยืนยันไม่ได้ ⇒ คง `TYPE_UNVERIFIED` · 🔴 **ห้ามย้ายเข้า `S-GOV`/`S-PO` เพื่อให้ชั้นลงตัว**
- ผู้ผ่านเกณฑ์ที่ยังเป็น `TYPE_UNVERIFIED` แม้หน่วยเดียว ⇒ **ห้ามสุ่ม** · resolve ก่อน หรือหยุดและรายงานจำนวน (เครื่องมือหยุดเอง)
- ไม่ใช้ขนาดไฟล์หรือยอดเงินเป็นชั้น

### 4.2 จำนวนและการจัดสรร

| ผู้ผ่าน (ไม่มี `TYPE_UNVERIFIED`) | ทำอะไร |
|---|---|
| ≥ 3 | สุ่ม 3 ตามชั้น |
| = 2 | ใช้ 2 + ประกาศข้อจำกัด |
| < 2 | **STOP ก่อนสุ่ม** · ห้ามลดเกณฑ์ · **ห้ามเปลี่ยนแบบการประเมินหลักเงียบ ๆ** · ส่งกลับ Bo/Gift ออกรุ่นใหม่ก่อนเลือกแบบอื่น |

จัดสรร: ชั้นที่มีผู้ผ่านได้ 1 ที่ก่อน (ตามลำดับ `S-GOV` → `S-PO`) · ที่เหลือให้ทีละที่แก่ชั้นที่ยังเหลือผู้ผ่านมากที่สุด · เสมอ ⇒ `S-GOV` ก่อน

### 4.3 seed และการสุ่ม

- **seed** = 16 หลักแรก (hex) ของ SHA-256 ของ **ไฟล์นี้** ที่ tag `final-eval-protocol-1.0.1` (ปลายบรรทัด LF = blob ใน git) ⇒ ค่าอยู่ใน `FREEZE_RECORD_1.0.1.md`

- **อันดับในชั้น** = เรียงตาม SHA-256(`"<seed>|<stratum>|<unit_id>"`) น้อยไปมาก · เลือก k อันดับแรกตามการจัดสรร

```
→ กระบวนการเฉลย (§5–§6)
→ unlock
→ blind run
```

## 5. เฉลย (gold truth)

ลำดับบังคับ: **primary annotation → second review → adjudication → Gold Truth finalize + seal → blind run**

1. **Gift = primary annotator และผู้ถือเฉลย** · ทำในพื้นที่ custody ตาม #11 (นอกพื้นที่ผู้พัฒนา · ไม่อยู่ใน repo สาธารณะ)
2. หน่วยรายการ = ตำแหน่งที่เปลี่ยนระหว่างสองฉบับ จัดชนิดตาม `t1b-posture-0.2.0` + ตำแหน่งตัวล่อ
3. ใช้เครื่องมือเทียบเซลล์ทั่วไป **ที่ไม่ใช่เอนจิน RedBook** ช่วยไล่ตำแหน่งได้ · บันทึกชื่อ/รุ่น · ผลเทียบเซลล์ชุดนี้คือตัวหารของ "การหายเงียบ"
4. ระหว่างทำเฉลย **ห้ามเห็นผลของระบบใด ๆ** บนไฟล์ชุดนี้
5. **ผนึก** = SHA-256 ของไฟล์เฉลย + เวลา + โหมด (§6.5) · ลงสาธารณะได้เฉพาะแฮช/เวลา/จำนวนรายการ
6. 🔴 **หลังผนึก ห้ามแก้เฉลยจากผลของระบบ** · ข้อผิดที่พบหลังเห็นผล ⇒ รายงานเป็นข้อจำกัด **ไม่คิดคะแนนใหม่**

## 6. การทบทวนครั้งที่สอง (predeclared subset · Bo ข้อ 1)

1. **ชุดสุ่ม** = ⌈25% × จำนวนรายการเฉลยทั้งหมด⌉ รายการแรก เมื่อเรียงรายการ **ทั้งหมด** ตาม SHA-256(`"<seed>|review|<item_id>"`)
2. **ชุดบังคับ** = ทุกรายการที่ชนิดเป็นท่าที REFERRED + ทุกรายการที่ผู้ทำเฉลยติดธง "กำกวม"
3. **ชุดทบทวน = ชุดสุ่ม ∪ ชุดบังคับ** · รายการที่อยู่ทั้งสองชุด **นับครั้งเดียว** · รายงานขนาดชุดสุ่ม · ชุดบังคับ · ส่วนซ้อน · รวม
4. ผู้ทบทวน: มนุษย์ · **ไม่ใช่ผู้พัฒนาเอนจิน (Giho) และไม่ใช่ Bo** · ไม่เห็นผลของระบบ · ติดป้าย **ปิดตาต่อป้ายของ Gift** แล้วจึงเทียบ · ตัวตนเก็บนอก repo สาธารณะ
5. **โหมด** `DUAL`/`SINGLE` บันทึก **ก่อน Gold Truth finalize + seal** · จัดผู้ทบทวนไม่ได้ทัน ⇒ `SINGLE` (Gift เป็น single primary annotator) + ประกาศข้อจำกัด · 🔴 ห้ามเปลี่ยนโหมดหรือวิธีหลังเห็นผล
6. ไม่ตรงกัน ⇒ บันทึกป้ายทั้งสอง + การหารือ + **disposition สุดท้ายโดย Gift พร้อมเหตุผล** · ทำก่อนผนึก
7. รายงานความสอดคล้องดิบ (x/y) **ของชุดสุ่ม** (ประมาณการตัวแทนทั้งชุด) และ **ของชุดบังคับ** แยกกัน · ไม่รายงาน kappa ในรุ่นนี้
8. ข้อจำกัด: การทบทวนตรวจ **ป้ายของรายการที่ไล่ไว้แล้ว** ไม่ได้ตรวจว่าไล่ครบ · ความครบพึ่งการเทียบเซลล์อิสระ (§5 ข้อ 3)
