## 6. สถาปัตยกรรมที่เสนอ — **ข้อเสนอ ไม่ใช่การตัดสิน**

```
   สมุดงาน baseline ─┐
                     ├─> AOWorkbookAdapter ─> T1BRecord ─> match_records ─> compare
   สมุดงาน final ────┘                            │                          │
                                                  │                          ├─> Finding + flags
                                                  └─> check_rollups ─────────┘
                                                                             │
                            (ยังไม่มี) ชั้นบริการของเว็บ  <─────────────────┘
                                       │
              storage/repository (มีอยู่แล้ว)   templates (มีอยู่แล้วครึ่งหนึ่ง)
```

**หลักที่เสนอให้ยึด**

1. เพิ่ม **ชั้นบริการ** คั่นกลาง — เว็บไม่เรียก `t1b/*` ตรง ๆ เพื่อให้เปลี่ยนเครื่องยนต์
   ได้โดยไม่รื้อหน้าจอ และให้ test ของเว็บไม่ต้องเปิดไฟล์ Excel จริง
2. **ห้ามแปลง `Finding` ของ T1B ให้เป็นรูปร่างของ T1A** — สองชั้นแยกขาดกันตาม `RES-D-24`
   ควรมีตารางเก็บผลของ T1B แยกต่างหาก
3. คิวต้อง **แยกชั้นก่อนแสดง** (A-09 ของเลน A) มิฉะนั้น 1,299 ใบจะใช้งานจริงไม่ได้
4. `READY` / `REVIEW REQUIRED` เป็น **ผลของกติกา ไม่ใช่ปุ่ม** — ต้องคำนวณจาก
   จำนวน finding ที่ยังไม่ถูกตัดสิน + สถานะ accounting + สถานะด่านตัวตนหน่วยงาน
