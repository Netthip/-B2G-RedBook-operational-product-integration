# PROTOCOL — source-registry-0.1.0 (#27)

## 1. สถานะความพร้อม

ระดับไฟล์ PDF (`pdf.status`)

| ค่า | ความหมาย |
|---|---|
| `FOUND` | หน้าเล่มมีลิงก์ และ 16 ไบต์แรกที่ได้เป็นลายเซ็น `%PDF` |
| `BROKEN_LINK` | หน้าเล่มมีลิงก์ แต่ไม่มีลิงก์ใดให้ PDF เช่น HTTP error, ต้องลงชื่อเข้าใช้ หรือได้ HTML |
| `NOT_FOUND` | อยู่ในรายการทางการ แต่หน้าเล่มไม่มีลิงก์ไฟล์ |
| `UNCHECKED` | ยังไม่ได้ตรวจลิงก์ ห้ามอ่านเป็นผ่านหรือไม่ผ่าน |

ระดับไฟล์ Excel (`excel.status`)

| ค่า | ความหมาย |
|---|---|
| `EXCEL_AVAILABLE` | มีลิงก์ที่เปิดได้อย่างน้อยหนึ่งลิงก์ ดู `verification_level` ประกอบเสมอ |
| `BROKEN_LINK` | หน้าทางการให้ลิงก์ไว้ แต่ไม่มีลิงก์ใดเปิดสาธารณะได้ |
| `NOT_LISTED` | ไม่พบใน**ส่วนที่ไล่อ่าน** (`excel.search_scope`) ซึ่ง**ไม่ได้แปลว่าไม่มี** |
| `UNCHECKED` | ยังไม่ได้ตรวจ |

ระดับการยืนยัน (`verification_level`)

- `FILE_SIGNATURE_VERIFIED`: ได้ลายเซ็นไฟล์จริง (`%PDF`, `PK..` + spreadsheet content-type)
- `EXTERNAL_VIEWER_PAGE_OPENS_FILE_NOT_VERIFIED`: ลิงก์ไปโฮสต์ภายนอก (Google Drive) ยืนยันได้แค่ว่าหน้าแสดงไฟล์เปิดได้
  ยังไม่ได้ยืนยันชนิดหรือเนื้อไฟล์ เพราะต้องดาวน์โหลดไฟล์

ภาพรวมรายเอกสาร (`availability`) มีลำดับความสำคัญดังนี้
`EXCEL_AVAILABLE` → `PDF_ONLY` → `BROKEN_LINK` → `NOT_FOUND`

`NOT_LISTED` ใช้ในข้อสังเกต `NOT_LISTED_IN_COUNTERPART` คือมีเอกสารในฝั่งหนึ่ง แต่ไม่อยู่ในรายการของอีกฝั่ง

## 2. การจับคู่ (fail-closed)

**คีย์โครงสร้าง**อ่านจากหัวเรื่องทางการ ไม่ใช้ลำดับในหน้า ไม่ใช้ความคล้ายของชื่อ

| ชนิดเอกสาร | คีย์ |
|---|---|
| ฉบับที่ 3 รายกระทรวง | `expenditure_by_ministry` + เลขเล่ม (เช่น `3(2)`) |
| ตัวบท ร่าง พ.ร.บ. / พ.ร.บ. | `appropriation_law` (ร่างกับฉบับประกาศใช้เป็นชนิดเดียวกัน) |
| ฉบับที่ 1, ฉบับที่ 2, งบประมาณโดยสังเขป, เอกสารภาษาอังกฤษ 3 ชนิด | ชนิดเอกสาร |
| รายงานประกอบอื่น ๆ | **ไม่มีคีย์ จึงไม่จับคู่อัตโนมัติ** แม้ชื่อจะเหมือนกันทุกตัวอักษร |

ผลการจับคู่

| สถานะ | เงื่อนไข |
|---|---|
| `MATCHED` | คีย์ตรง มีฝั่งละหนึ่งเอกสาร และสำหรับฉบับที่ 3 **ชุดกระทรวงในเล่มต้องตรงกันทุกชื่อ** |
| `REVIEW_REQUIRED` | คีย์ตรง แต่ชุดกระทรวงต่างกันหรืออ่านไม่ได้ จึงให้คนยืนยัน |
| `CANNOT_DETERMINE` | คีย์เดียวกันมีมากกว่าหนึ่งเอกสารในฝั่งเดียว |

ชนิดคู่

- `SAME_YEAR`: ร่าง ↔ พ.ร.บ. ปีเดียวกัน
- `CROSS_YEAR`: ขั้นเดียวกัน ปีติดกัน (2568↔2569, 2569↔2570) ทั้ง ร่าง↔ร่าง และ พ.ร.บ.↔พ.ร.บ.

คีย์ที่มีฝั่งเดียวจะไม่หายเงียบ แต่เข้า `unpaired[]` และออกเป็นข้อสังเกต `NOT_LISTED_IN_COUNTERPART`

**เงื่อนไขบัญชีครบ** (ตรวจด้วย test): ทุกเอกสาร = อยู่ในคู่ ∪ มีฝั่งเดียว ∪ ไม่มีคีย์

## 3. ความสามารถเทียบ (หมวด A–D)

| หมวด | สถานะ | ขอบเขต |
|---|---|---|
| A ความครบของชุดเอกสาร | **รองรับ** | ระดับเล่ม/ไฟล์: จำนวน · PDF · Excel · หาย · ไม่อยู่ในรายการ · ลิงก์เสีย · โครงสร้างฉบับ/เล่ม |
| B โครงสร้าง ระดับเล่ม | **รองรับ** | ชุดกระทรวงในเล่มเปลี่ยน · กระทรวงย้ายเล่ม |
| B โครงสร้าง ระดับรายการ | **ยังไม่รองรับ** | ต้องอ่านเนื้อไฟล์ |
| C ตัวชี้วัด | **ยังไม่รองรับ** | ตัวชี้วัดอยู่ในเนื้อ PDF และยังไม่มีตัวอ่าน PDF |
| D ยอดเงิน | **ยังไม่รองรับกับแหล่งทางการ** | เครื่องตรวจเทียบยอดได้เฉพาะ AO workbook ที่ผู้ใช้นำเข้า (workflow เดิม #7/#14) |

แต่ละคู่มี `comparison` พร้อมเหตุผล ค่ามี 3 ระดับ

- `NOT_SUPPORTED`: แหล่งมีแค่ PDF หรือขั้น พ.ร.บ. ไม่มี Excel รายเล่ม
- `NOT_VERIFIED`: มี Excel ทางการทั้งสองฝั่ง แต่**ยังไม่ได้ตรวจโครงสร้างไฟล์** เพราะต้องดาวน์โหลด (รอคำตัดสิน)
- คู่ที่ยังไม่ `MATCHED` จะไม่ถูกเทียบเนื้อหาเลย (`PAIR_NOT_CONFIRMED`)

## 4. สิ่งที่ทะเบียนนี้ไม่อ้าง

- ไม่อ้างว่าเอกสาร "ถูก/ผิด" เพราะหมวด A เป็นข้อสังเกตของชุดเอกสารเท่านั้น
- ไม่อ้างว่า "ไม่มี Excel" เมื่อไม่พบ อ้างได้แค่ว่าไม่อยู่ในส่วนที่ไล่อ่าน
- ไม่อ้างว่าลิงก์เปิดได้ตลอดไป ใช้ได้ ณ `verified_date` เท่านั้น
- ไม่มีตัวเลขเงินจริงและไม่มีค่าคาดหวังของข้อมูลจริงในโค้ดหรือ test
- ไม่เปลี่ยน frozen evaluation และไม่เพิ่ม rule ใน engine
