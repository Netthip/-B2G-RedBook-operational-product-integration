### 3.1 ค่าเงิน (`extract.Amount`) — ค่า · ความละเอียด · หน่วย · ที่มา แยกกัน

| ฟิลด์ | ความหมาย | หลักฐาน |
|---|---|---|
| `value` | Decimal ตามที่พิมพ์ (ไม่ปัด · ไม่เติมทศนิยม) · `""` เมื่อ `status = dash` | `ev` = บรรทัดของค่า (หน้า + กรอบ + ข้อความดิบ) |
| `raw` | ข้อความดิบในเซลล์ ("0.1760" · "960,000" · "-") | — |
| `decimals` (คำนวณจาก `raw`) | จำนวนทศนิยมที่พิมพ์ | — |
| `unit` · `scale` | หน่วย (บาท/ล้านบาท) · ตัวคูณเป็นบาท (`text.UNIT_SCALE`) | `unit_ev` = บรรทัดที่หน่วยมาจาก · `None` = ไม่มีในเอกสาร |
| `unit_origin` | `row` (คำหน่วยในแถว) · `text_column` (คอลัมน์หน่วยนับ) · `table_decl` (บรรทัด "หน่วย : …") = **มีในเอกสาร** · `profile_default` (ค่าตั้งต้นตามชนิดตาราง) · `assumed` (สมมติเป็นบาท) = **ไม่มีในเอกสาร** | — |
| `column` · `column_origin` | ชื่อคอลัมน์ (หมวดงบ/ปี/ช่วงปี/รวม) · `header` · `header_two_line` · `range_header` · `nearest_column` · `label` (จากป้ายแถว) · `book_year` (จากปีงบของเล่ม) | `column_ev` = บรรทัดหัวตาราง (หรือแถวเดียวกันเมื่อคอลัมน์มาจากป้าย) |
| `tolerance` · `rounding_tolerance` (คำนวณ) | ครึ่งหนึ่งของหลักสุดท้ายที่พิมพ์ · เกณฑ์ที่กฎใช้ = `rounding_tolerance` (เฉพาะหน่วยที่ใหญ่กว่าบาท · บาท = 0) | — |

- **precision ไม่ใช่ความเชื่อมั่น:** ใช้กำหนดเกณฑ์ปัดเศษอย่างเดียว · เกณฑ์ของกฎ = ผลรวม `tolerance` ของทุกค่าที่เกี่ยว (`compare._sum_tol` / `_baht_tol`) เช่น พิมพ์ 1 ตำแหน่ง 1.2 + 1.3 ↔ 2.6 ไม่ยก แต่พิมพ์ 4 ตำแหน่ง 1.2000 + 1.3000 ↔ 2.6000 ยก (`test_sum_tolerance_follows_printed_precision`)
- **การแสดงผล:** `text.fmt` แสดงตามทศนิยมที่พิมพ์ — เลิกเติมศูนย์ให้ครบ 4 ตำแหน่ง · ค่าที่แปลงเป็นบาทไม่แสดงศูนย์ท้ายจากการคูณ
- **ว่าง / ขีด / ศูนย์ / อ่านไม่ได้ / ไม่พบ แยกกัน:**
  - ขีด = `BookFacts.dashes` (`status = dash`)
  - ศูนย์ = `amounts` ค่า 0
  - ช่องว่าง = `BookFacts.blanks` (`status = blank`) — แถวมีอยู่และมีตัวเลขในช่องอื่น แต่ช่องนี้ไม่มีอะไรพิมพ์ · ฉบับหนึ่งว่างอีกฉบับมีตัวเลข = `blank_vs_value`
  - ไม่มีระเบียนเลย = "ไม่พบ" — การไม่มีระเบียนไม่ได้พิสูจน์ว่าช่องว่าง
  - แถวที่มีตัวเลขแต่จัดไม่ได้ = `coverage.unparsed` ("อ่านไม่ได้")
  - ฉบับหนึ่งขีดอีกฉบับมีตัวเลข = ข้อสังเกต `dash_vs_value` ไม่ใช่ "มีเฉพาะฉบับ"

### 3.2 แกนสถานะ (แยกกัน · เกิดร่วมกันได้)

| แกน | ค่า | ใช้ทำอะไร |
|---|---|---|

  - ปีงบของเล่ม `uncertain`/`conflict`/`not_found` = คำเตือนต่อฉบับบนหน้าผล ที่โหมดที่เลือกเองไม่กลบ
- **ไม่แสดงหน่วยสมมติเหมือนอ่านจากเอกสาร:** หน้าหลักฐานแสดงที่มาหน่วยคู่กับค่า ("หน่วยตามค่าตั้งต้นของโปรไฟล์ — ไม่พบในเอกสาร") และค่าที่พิมพ์จริง · CSV มีคอลัมน์ ค่าดิบ / หน่วย / ที่มาหน่วย / สถานะ ต่อฝั่ง

### 3.3 Identity — กติกา ID ที่ใช้จริง (`extract.resolve_node_keys` · `compare`)

1. **โหนด** (แผนงาน/ผลผลิต/โครงการ/กิจกรรม):
   - ฐาน = `ระดับ:label_key(ชื่อ)` (ตัดเลขข้อ · ตัดคำนำระดับ · โครงคำ)
   - ไม่ขึ้นกับลำดับในเล่ม — สลับลำดับได้กุญแจเดิม
2. ฐานเดียวกันพบใต้ **แม่ที่ระบุต่างกัน ≥ 2 แบบ** = คนละรายการ → `ฐาน@กุญแจของแม่` (ไล่เส้นทางขึ้นไปเมื่อแม่ก็ซ้ำ)
   - "แม่ต่างกัน" ตัดสินด้วย **กุญแจจริงของแม่ (เส้นทางที่ระบุตัวแล้ว)** ไม่ใช่ชื่อแม่ (0.5.0 · REVIEW 6360210542):
     ลูกชื่อเดียวกันใต้แม่ชื่อเดียวกันที่อยู่คนละแผนงาน = คนละรายการ (เดิมรวมเป็นกุญแจเดียว)
   - ครอบคลุมทั้งชื่อซ้ำต่างแผนงาน และชื่อซ้ำต่างผลผลิต/โครงการในแผนงานเดียวกัน
   - ข้อความในรุ่นก่อนที่ว่า "ชื่อซ้ำต่างแม่ = ชนกัน" ใช้ไม่ได้แล้ว
3. ครั้งที่พบ **โดยไม่มีแม่** (หรือแม่เองกำกวม) ของฐานที่แยกตามข้อ 2 = กำกวม → ไม่เดาว่าเป็นของแม่ใด · บันทึก `ambiguous_parent` + รายการกุญแจที่เป็นไปได้
   - ลูกหลานของแถวที่ระบุตัวไม่ได้/ของโหนดที่โครงคำชนกัน สืบทอดปัญหา (`parent_unidentified` · `parent_collision`) —
     ไม่ทำข้อสังเกตแยก แต่ทุกค่าที่ผูกกับลูกหลานติดธงต้องยืนยัน (`extract.ISSUE_FLAGS` · `node_flags`)
4. กุญแจเดียวกันแต่ชื่อจริงต่างกันที่สระ/วรรณยุกต์ (`text.exact_key` คงเครื่องหมาย):
   - **ภายในเล่ม:** ระบบแยกไม่ได้ว่ารายการเดียวหรือคนละรายการ → บันทึก `skeleton_merge` พร้อม **ทุก occurrence** ·
     ทุกค่าเงิน/ขีด/ช่องว่างของโหนดนั้นติดธง `identity_collision` (ต้องยืนยัน) · ผลรวมที่มีโหนดนั้นเป็นองค์ประกอบติดคำเตือน
     จึงใช้สรุปไม่ได้จนคนยืนยัน (`mark_identity`)
   - **ช่องเดียวกัน (ตาราง·โหนด·คอลัมน์) มีหลายค่าที่ต่างกัน** = `duplicate_cell` — เก็บทุกค่า แสดงทุกค่า ติดธงทุกค่า
     (เดิมตัวเทียบใช้ค่าสุดท้ายและค่าอื่นหายเงียบ) · ค่าเดิมที่พบซ้ำในหลายตาราง ไม่นับเป็นปัญหา
   - ชุดพัฒนาพบจริงก่อนแก้: แถว "รายจ่ายประจำ/ลงทุน" ใต้ภารกิจพื้นฐาน/ภารกิจเพื่อการพัฒนาในตารางเงินนอกงบประมาณ

### 3.4 นโยบายปัดเศษ (`compare.ROUNDING_POLICY` · `Finding.tolerance_basis`)

- เกณฑ์ครึ่งหลักสุดท้าย (ผลรวม `rounding_tolerance` ของทุกค่าที่ใช้) ใช้เฉพาะค่าในหน่วยที่ใหญ่กว่าบาท (ตารางล้านบาท) และเป็น
  **สมมติฐานของกฎ** ว่าแต่ละค่าถูกปัดจากบาทอย่างอิสระ — **เอกสารไม่ได้ระบุวิธีปัด** จึงไม่ใช่ข้อเท็จจริงที่พิสูจน์จากหน่วย
  (REVIEW 6360210542) · ทุกข้อสังเกตบันทึก `tolerance_basis = assumed_independent_rounding` และแสดงที่มานี้ในหมายเหตุ/CSV/หน้าหลักฐาน
- **กฎเคร่งครัด (เกณฑ์ 0 · `tolerance_basis = strict`):** ค่าหน่วยบาททุกตาราง — ผลรวมรายการในรายละเอียด · รายการผูกพัน
  (วงเงิน = ผลรวมปี · วงเงิน = เงินงบประมาณ + เงินนอกงบประมาณ) · ตารางที่พิมพ์เป็นบาท (เดิมได้เกณฑ์ 0.5 บาทต่อค่า ซึ่งกลบ
  ส่วนต่าง 1 บาทได้เมื่อมีหลายค่า — แก้ใน 0.5.0 · `test_rounding_tolerance_is_a_declared_assumption_*`)
- ส่วนต่างที่อยู่ในเกณฑ์ = ไม่ยกเป็นข้อสังเกต แต่ **ไม่ได้แปลว่าตรงเป๊ะหรือถูกต้อง** · ไม่รับ tolerance เป็นกฎทั่วไปเพราะเทสต์ผ่าน
- ทุกข้อสังเกตของกฎผลรวม/ข้ามตารางแสดง ยอดที่พิมพ์ · ผลรวมที่คำนวณ · **ส่วนต่าง** · **เกณฑ์ที่ใช้** (หรือ "กฎเคร่งครัด") ·
  องค์ประกอบทุกค่า — ทั้งในหน้าหลักฐานและ CSV (คอลัมน์ "องค์ประกอบที่ใช้คำนวณ" · "เกณฑ์ปัดเศษ")

เส้นทาง: `PDF → reader (อักขระตามลำดับ stream → คำ) → scope → layout (แถว/คอลัมน์) → extract (records + ที่มา + ธง
+ identity) → compare (matching + กฎเงิน/roll-up/MTEF/ตัวชี้วัด/ข้อความ/รูปแบบ + ภายในเล่ม) → Finding (+ caveats) →
หลักฐาน A/B → คำตัดสินของคน → Audit/CSV` · OCR ไม่อยู่ในเส้นทาง

## 9. ก่อนเรียกว่า "พร้อมประเมิน" (ตอบ REVIEW 6340074844 ข้อ 5–6 · ยังไม่ผ่าน)

1. **สุ่มทวนระเบียนกับภาพ** — `scripts/pdfpair_sample_records.py` สุ่มแบบแบ่งชั้น (ค่าเงิน · ขีด/ช่องว่าง · ชื่อโหนด ·
   ตัวชี้วัด · ข้อความ · หลักฐานปี) ด้วย seed ที่บันทึก + ตัดภาพบรรทัด → แบบทวนให้คนติ๊ก ตรงภาพ/ไม่ตรง/ไม่แน่ใจ
   (แบบทวนอยู่ในพื้นที่ private ของ Gift · ยังไม่ได้ทวน) · "ไม่มีแถวอ่านไม่ได้" ไม่ได้พิสูจน์ว่าอ่านครบหรืออ่านถูก
2. **รายการอ้างอิงอิสระก่อนเรียก "ยกเกิน"** — เอกสารที่เผยแพร่ไม่ใช่เฉลยว่าภายในต้องสอดคล้องทุกจุด · ข้อสังเกตที่ระบบยก
   จะนับว่าเกินได้ก็ต่อเมื่อเทียบกับรายการที่คนทำอิสระจากผลระบบ (แบบบันทึกตรวจชุดพัฒนาด้วยมือ ฉบับ ๒)
3. **โปรโตคอลประเมิน** (#43 · ต้องให้ Bo ตรวจก่อนตรึง):
   - แยกผลการตรวจจับจุดต่าง ออกจากความพอใจ/ความเห็นต่อเครื่องมือ
   - การเปลี่ยนที่ตั้งใจ (การปรับลดจริง · การเปลี่ยนระหว่างปี) **ไม่นับเป็นยกเกินอัตโนมัติ**
   - กฎข้ามปี: ตรวจฐานปี/ขั้นเอกสาร/การปรับปรุงที่อนุญาตก่อนบอกว่า "ควรตรง"
4. ลำดับ: Gift ทวนชุดพัฒนา → แก้/ตรวจ regression → ตรึงรุ่น + วิธีนับ + แบบบันทึก → ประเมิน
   (Bo เห็นชอบลำดับ แต่ยังไม่รับรอง readiness)
