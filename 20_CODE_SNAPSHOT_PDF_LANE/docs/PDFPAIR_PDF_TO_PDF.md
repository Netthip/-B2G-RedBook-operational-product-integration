# เทียบเล่มเอกสารงบประมาณ PDF ↔ PDF (`redbook.pdfbook` · pdfbook-0.4.0)

สายผลิตภัณฑ์แยกจากเครื่องยนต์ T1B (Excel) — อ่าน **ชั้นข้อความ** ของ PDF สองฉบับ (ไม่ใช้ OCR)
แล้วเสนอข้อสังเกตพร้อมหลักฐานหน้าเอกสาร ผู้ตรวจเป็นผู้ตัดสินทุกข้อ

> 🔴 **สถานะโปรไฟล์ = `SYNTHETIC_CALIBRATED`** — ปรับเทียบกับเล่มสังเคราะห์เท่านั้น
> (`scripts/demo_redbook_book_pdf.py`) · ยังไม่ได้ปรับกับเล่มจริงชุดพัฒนาที่ได้รับอนุญาต ·
> ผ่านเทสต์ ≠ อ่านเล่มจริงได้ · ทุกหน้าจอแสดงสถานะนี้

## สิ่งที่ตรวจ (ตามรายการของกิ๊ฟ 21 ต.ค. 2569)

| หัวข้อ | เทียบสองฉบับ | ตรวจภายในเล่ม |
|---|---|---|
| ยอดรวมและวงเงินตามหมวดงบรายจ่าย (หัวเล่ม · ตารางสรุป · รายละเอียด · เงินนอกงบประมาณ) | ✓ | ผลรวมหมวด = ช่องรวม · ลูก = แม่ · รวมทั้งสิ้น = ผลรวมแผนงาน · รายละเอียด ↔ ตารางสรุป |
| รายจ่ายประจำ / รายจ่ายลงทุน | ✓ | ประจำ + ลงทุน = รวม · ตาราง ↔ ตารางสรุป |
| แผนงาน ผลผลิต/โครงการ กิจกรรม (เพิ่ม · หาย · ชื่อเปลี่ยน · ย้ายแผน) | ✓ (ชื่อเปลี่ยน = **คู่ที่เสนอ** ไม่จับคู่ให้อัตโนมัติ) | — |
| รายการที่เสนอตั้ง / ไม่เสนอตั้ง | ✓ | ยอดหมวด = ผลรวมรายการที่พิมพ์ |
| วงเงินรวมโครงการและรายการผูกพันข้ามปี | ✓ (ข้ามปี: "ผูกพันปี Y" ในเล่มก่อน ↔ "ปี Y ตั้งงบประมาณ" ในเล่มนี้) | วงเงินทั้งสิ้น = ผลรวมรายปี |
| ประมาณการรายจ่ายล่วงหน้า (MTEF) | ✓ | ปีงบในตาราง ↔ ตารางสรุป |
| ตัวชี้วัดและค่าเป้าหมาย (ระดับหน่วยงาน / ผลผลิต / โครงการ) | ✓ ชื่อ · หน่วยนับ · เป้าหมายรายปี | — |
| วิสัยทัศน์ พันธกิจ ผลสัมฤทธิ์ เป้าหมายการให้บริการ วัตถุประสงค์ | ✓ พร้อมแสดงส่วนที่ข้อความต่าง | — |
| ส่วนที่อ่านไม่ได้ | หน้าที่ไม่มีชั้นข้อความ · แถวที่มีตัวเลขแต่จัดหมวดไม่ได้ · หัวข้อที่ฉบับหนึ่งพบอีกฉบับไม่พบ | — |

โหมด: **ปีเดียวกัน** (ร่าง พ.ร.บ. ↔ พ.ร.บ.) ทุกค่าที่ต่าง = ข้อสังเกต · **ข้ามปี** (เล่มปี Y−1 ↔ ปี Y)
การเปลี่ยนแปลงระหว่างปี = *ข้อมูลประกอบ* (ไม่ต้องตัดสิน) ส่วน **ตัวเลขปีเดียวกันที่ปรากฏในทั้งสองเล่ม
แต่ไม่ตรงกัน** = ข้อสังเกตที่ต้องตรวจ

## ใช้งาน

งานตรวจ → **เทียบเล่ม PDF ↔ PDF** → แนบ PDF ฉบับ A/B (ระบบเก็บ SHA-256) → ใส่ชื่อหน่วยงาน
(เล่มรวมหลายหน่วยงาน) หรือกำหนดช่วงหน้าเอง → เทียบเล่ม → ผลแยก 10 หัวข้อ → เปิดหลักฐาน A | B
(ภาพหน้า PDF พร้อมกรอบบรรทัด) → บันทึกผล 6 แบบ (เปลี่ยนผลเดิมต้องมีเหตุผล · มี Audit) → ส่งออก CSV

เส้นทาง: `/projects/{pid}/pdfpair` · `/pdfpair/runs/{rid}` · `/pdfpair/runs/{rid}/f/{fid}` · `…/{A|B}.png` · `…/export.csv`

## ขอบเขตและข้อห้าม

* product backend = pdfplumber + pypdfium2 เท่านั้น (ไม่มี fallback ไป PyMuPDF · มีเทสต์ AST)
* `redbook/pdfbook` ไม่ import `redbook.t1b` · ไม่มีโค้ดเครือข่าย · route เรียกผ่าน `services/pdfpair` เท่านั้น
* ไฟล์ที่แนบต้องมี SHA-256 ตรงกับตอนแนบ — ไม่ตรง = ไม่อ่าน · ภาพหลักฐานเปิดไม่ได้ถ้าแนบไฟล์ใหม่แทน
* ไม่เปลี่ยนตาราง/ผลของ T1B · ไม่ป้อนผลเข้าเครื่องยนต์

## ก่อนใช้กับเล่มจริง (ต้องทำตามลำดับ)

1. **โบเห็นชอบชุดพัฒนาและชุดทดสอบ** — กติกาเดิม: ยังไม่อนุญาตเปิด/ดาวน์โหลดเล่ม candidate
   แม้กิ๊ฟรันเอง · ชุดพัฒนาต้องแยกจากชุดประเมิน · ห้ามใช้หน่วยที่กันไว้ (holdout)
2. ปรับโปรไฟล์ (`redbook/pdfbook/profile.py`) กับ **ชุดพัฒนาเท่านั้น** — ข้อที่คาดว่าต้องปรับ: ลำดับอักขระไทย
   ที่ถอดจาก PDF · หัวตารางที่แตกหลายบรรทัด · ตำแหน่งคอลัมน์ · คำบ่งชี้หัวข้อจริง · หน่วยของแต่ละตาราง ·
   หัวข้อคาบเกี่ยวหน้า · เล่มปี 2568 (สารบัญรูปแบบต่าง)
3. ขึ้น `PROFILE_VERSION` + เปลี่ยน `PROFILE_STATUS` + เพิ่มเทสต์ แล้ว **ตรึงรุ่น** (commit/tag)
4. จากนั้นจึงทดสอบกับชุดทดสอบ (เฉลยของผู้ปฏิบัติงานที่เขียนไว้ก่อนเห็นผลระบบ) **ครั้งเดียว** — ห้ามแก้โปรไฟล์
   หลังเห็นเฉลย (แก้ = รุ่นใหม่ ไม่ทดสอบซ้ำกับชุดเดิม)
